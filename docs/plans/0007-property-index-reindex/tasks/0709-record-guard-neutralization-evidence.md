# Record Guard Neutralization Evidence In The Safety Case

The repair safety case records, among its known gaps, that its guards had named regressions but no disabled-guard runs. This plan closes that gap before review rather than after. For every refusal and preservation guard the reindex introduces, add a named regression that reaches the production entry (`plan_reindex` or `PreparedReindex::apply`), then neutralize the guard alone in an isolated source state, run the test, record the observed failing result, and restore the code.

Guards in scope: unsupported type refused; a mount-fragment storage name, a definition whose `PathFilter` Oak cannot construct, a definition whose parent is not `/oak:index`, a lane mid-run at `/:async/async-reindex` and a node that is not `oak:QueryIndexDefinition` each refused with its typed variant (regression through `plan_reindex`); `valuePattern` regular expression refused; dangling lane checkpoint refused without `--from-head`; `--from-head` on a counter with a dangling or absent lane performing the reset — hidden children removed, retained ones kept, every visible property untouched, nothing built (neutralization: rebuild from the head instead; the regression asserts no hidden child and every visible property unchanged; the Oak-side proof is task 0712's reset scenario); an absent lane treated as a dangling checkpoint; a multi-valued `reindexCount` refused; the residue refusal for an operator-named work directory (through `plan_reindex`; neutralization: accept the residue and proceed); the disabler's flag written only under its predicate (neutralization: predicate always true; the disabled-`supersedes` test of 0706 fails); async definition indexed from its lane checkpoint (neutralization: index from the head; the regression compares the rebuilt counter against the checkpoint-state oracle);
