# Prove The Property Reindex Against Oak's Own Reindex

The `property_reindex` phase holds froe to the strongest oracle available: Oak rebuilding the same indexes from the same content. A booted Sling writes content of its own before any request arrives (discovery, job and distribution nodes under `/var`, each keyed by the fresh instance identifier), so a rebuild on an un-booted copy could never match a rebuild on a booted one; both rebuilds must therefore index the very same store. The phase boots a Sling on a copy of the fixture, flags every property-family definition through the Sling POST servlet (`reindex=true` with `@TypeHint=Boolean`); the synchronous ones are rebuilt inside that commit, the counter by the `async` lane, and the phase waits for every `reindex` flag to read `false` before stopping Sling and extracting the store — the *Oak-rebuilt store*. Before comparing, the phase checks that the extracted async index is canonical — a lane cycle that ran between Oak's rebuild and the stop maintains the counter incrementally, and the counter editor removes a `:cnt` that reached zero but never the node it sat on, so a deletion in that window leaves a `:cnt`-less mirror node no rebuild produces; plan 0006's counter reader reports such nodes, and when any exists the phase repeats the boot, flag, wait and stop sequence (bounded to three attempts; exhausting them fails the phase naming the non-canonical condition, never skips the comparison) rather than compare. It then copies that extracted store, resets each rebuilt definition's bookkeeping on the copy through a small writer helper in a new `definition_edits.rs` (`reset_reindex_bookkeeping`, `remove_hidden_children`; registered in `main.rs` and shared with plans 0008 and 0010) built on the public API — re-emitting the definition node with `RecordWriter::write_node`, its hidden children re-attached by identity, and splicing it up the spine with `rewrite_node_with_child_edits`, as `phase_writing.rs` splices content today (`reindex = true`, `reindexCount` set to the extracted value minus one, so that froe's own single increment lands back on the extracted value, whatever the attempt count), and runs `froe index reindex --yes` for the same definitions on that copy: the synchronous ones from the head both stores share, the counter from the lane checkpoint Oak's last cycle recorded in `/:async`, which is the state the extracted counter index reflects. Then the comparison between the copy and the extracted store. The phase lives in a new `phase_property_reindex.rs`, registered in `main.rs`; one file per plan's phases keeps each under the thousand-line gate.

**Steps:**

1. Sling helpers in `sling.rs`: `sling_set_property(port, path, property: SlingProperty { name, value, type_hint })`, `sling_wait_until_reindexed(port, index_path)` polling the definition's JSON until `reindex` is `false` and `reindexCount` has advanced, and `sling_install_query_probe(port)` posting a JSP under `/apps/froe/query` that runs a JCR-SQL2 statement from a request parameter and prints one path per row, or the `plan` column for an `EXPLAIN` statement — the Sling GET servlet in this image ships no query servlet, so the probe is the only way to run a query through the live engine.
2. `digest.rs`: `ExpectedDigestDelta::Subtrees(&[…])` accepting differences only under the listed prefixes (beside the existing `None` and `CheckpointsOnly`), and a new `digest_store_excluding_properties(store, subtrees, prefixes)` helper beside `digest_store_excluding` that passes `--exclude-property-prefix :count_`.
3. Oracle comparison: for every rebuilt definition, `froe digest --exclude-property-prefix :count_` restricted to `/oak:index/<name>` must be identical between the extracted store and froe's copy — `reindexCount` included, since the helper reset it and froe incremented it once as Oak did, and the presence or absence of `:index`, `:references` and `:weakreferences` included, since Oak creates the latter two and the counter's data node lazily. A difference names the first differing line; this is the assertion the phase exists for.
4. Content preservation: the full digest of the copy before and after froe's run with `Subtrees(["/oak:index"])` proves nothing outside the definitions changed; `froe check` passes at the new head.
5. Oak consumption: boot Sling on froe's store; `assert_oak_consumed_store_as_written`; add Oak's own reindex-start log line, `Reindexing will be performed`, to a new `OAK_REINDEX_MARKERS` set asserted absent in `oak.rs`; through the probe, run one query per index type — `[jcr:uuid] = …`, `[sling:resourceType] = …` under a path, `ISDESCENDANTNODE` with a node-type restriction, a reference lookup — and require identical result sets on every sample, and identical `EXPLAIN` plans on the samples whose plan text carries no counter-derived number — the unique-strategy `uuid` plan (whose text prints `estimatedCost: 2.0` for a unique hit — Oak's fixed cost overhead plus a best cost of zero, deterministic because the unique strategy counts a single-value restriction from the number of elements in the stored `entry` array) and the `reference` plan (no cost line) — while the mirror-strategy samples (`[sling:resourceType]`, the `ISDESCENDANTNODE` query with a node-type restriction) are compared on their result sets only, because a property index's plan text prints an `estimatedCost:` that the mirror strategy's count derives from the randomized `:count_*` counters froe omits by recorded deviation, and index selection between competing mirror indexes may differ for the same reason.
6. Convergence: a second `froe index reindex --yes` on froe's store renders the hidden children (`:index`, `:references`, `:weakreferences`) identically under the same digest, the definition node itself excluded because `reindexCount` increments on every run.
7. The reset: on a further copy of the extracted store, remove the `async` lane's checkpoint with `froe checkpoint remove --yes <name>`, run `froe index reindex --yes --from-head --index /oak:index/counter`, assert the definition has no hidden child and every visible property unchanged, boot Sling, wait for the lane's cycle, assert Oak logged `Failed to retrieve previously indexed checkpoint`, advanced `reindexCount` by exactly one and rebuilt the counter from scratch (`:index` present and canonical per task 0607's reader); then stop Sling, extract that store and compare Oak's from-scratch counter against a froe rebuild on a copy from the lane checkpoint that cycle recorded (the oracle shape of steps 1–3, bookkeeping reset through `definition_edits.rs`), since the second boot's instance-keyed content makes any comparison against the first oracle non-deterministic; record the scenario in the run record. The canonical-index verdict and the attempt on which it passed are written to `canonical-index-property.txt` in the work root, as `generate` writes `oak-build.txt` — a per-phase name, because plan 0010's phase writes its own `canonical-index-lucene.txt` into the same work root and `write_run_record` runs once after both phases — so `write_run_record` can read them even when the script runs a phase alone in its own process.

- **Done when:** the phase passes against the pinned image with the per-definition digest comparison identical, the query and plan comparisons equal, the reset scenario ending in Oak's own from-scratch rebuild, and a deliberately wrong key encoding (space encoded as `%20` instead of `+`) makes the comparison fail on the affected index, and the stable host gate passes (`--all-features`, so the interop suite is compiled and linted).
