# Write The Property Reindex Safety Case

`docs/high-risk-changes.md` asks for the safety case before the code, so that the first review is about whether the design is correct rather than about discovering its proof obligations one at a time. Write it as the `### Safety case` section of this plan's `ARCHITECTURE.md`, in the form the merged-maintenance and repair cases (plans 0004 and 0001) take, as the living record the later tasks fill in: the fault table gains rows as cutpoints are armed (0708), the guards table gains rows as guards land (0709), and the interoperability record and verification report are written by the review task (0714).

**Steps:**

1. **Scope and retention.** Default-safe work and opt-in side effects: the rebuild is default-safe, while `--from-head` authorizes exactly two side effects on a definition whose lane checkpoint is dangling or absent, and nothing else: a from-head rebuild of a mirror or unique definition, whose replay leaves its entries unchanged, and the reset of a counter (in plan 0010, of a Lucene definition) — hidden children removed, nothing rebuilt, Oak's next cycle rebuilding from scratch. What must survive unconditionally: the content tree, every checkpoint, every definition not selected, every property of a selected definition other than `reindex`, `reindexCount`, `corrupt`, a `seed` the counter run creates when absent, the `async` property of a definition parked at `async = async-reindex` (removed as the switch-back removes it, task 0706), and the hidden `:disableIndexesOnNextCycle` (written under Oak's own disabler predicate), every hidden child flagged `retainNodeInReindex`, every visible child of a selected definition including one froe does not model (plan 0007 writes none through `DefinitionEdits.visible_children`; task 0706's digest comparison is the regression), `/:async` in full. What is deliberately dropped: the previous hidden children of a selected definition. What the run never touches: lane checkpoints, `journal.log` history, archives.
2. **Authoritative state.** The preview is advisory and lockless; `PreparedReindex::prepare` runs the repository-shape check and the two pre-lock apply-identity gates, takes `repo.lock`, repeats both, replans from disk, fingerprints the directory, certifies the archive number and runs the metadata-source gate; `apply` rechecks the fingerprint and the path identity and opens through `open_prepared`; the facts rechecked under the lock: the definition set, each definition's type and lane, the lane checkpoint's existence and its root record, the disabler verdict selection reads over the head's other definitions, the definition record, the head — and that no record identity from the lockless plan survives the replan.
3. **Mutation and publication order.** The existing `### Mutation and publication order` section of `ARCHITECTURE.md` *is* the safety case's table (cited by its heading, never copied, so a later edit cannot leave two versions to review), and this task only fills in the named regression each row will get.
4. **Interruption prefixes.** For returned errors and abrupt death at each boundary: the store is either unchanged plus unreferenced archives at the head's generation, or at the new head with every new subtree verified; there is no third state. State that `compare_and_set_head` is an in-memory move and that `flush` fsyncs archives before the single journal append, so the two cutpoints around it observe the same on-disk prefix.
5. **Observed outcomes.** `ReindexOutcome` reports per definition a typed outcome — rebuilt, with entries, keys and bytes; reset, with the hidden children removed and the retained ones kept; or `NothingToDo { reason }` (no removable hidden child), which never moves the head — and the head before and after, from observed operations, never inferred from text.
6. **Resources.** The sort budget (one per definition, a shared `SortBudget` charge handle the reference collector's two run sets hold together rather than dividing, in bytes, configurable, default stated), the spill directory's worst case (total entry bytes ≈ one path string per indexed value; for `nodetype` that is every node path once per type value; transiently up to fan-in times the budget more during a reduction pass, until the merged inputs are unlinked), the open-file bound of the merge (the fan-in task 0702 declares plus one, never the run count, with one merge live at a time so a reference definition's two run sets do not double it), the asymptotic time cost (two walks of the state per confirmed run — the counting walk `prepare` performs under the lock and the collecting walk of `apply`; a preceding `--dry-run` adds the lockless plan's — plus one pass over the rebuilt entries for the tail's entry-side verification and the two `verify_node_tree` passes over the new records, before publication and after the reopen; the sort's n log n plus one merge pass over the spill bytes per fan-in level; and the trie writer's single pass over the sorted sequence — pinned by the visited-node counter of 0704, the merge-pass counter of 0702 and the write counter of 0703), the trie writer's state bound — for the mirror strategy the widest fan-out on one path, the trie root `:index` included (one child per distinct key); for a unique or reference index the `:index` (or `:references`) node itself, one child per key — in both cases a resident state of distinct keys times one name plus one record identifier, because `ChildNodesToWrite::Many` holds every child of a wide node while it is written: the one key-proportional term the bounded-memory case admits, reported per definition in the plan's estimate (the entry count as the upper bound for a mirror definition, the exact distinct-key count in the outcome) — the counters' `credited_by_path` maps, which outlive their builds — one entry per credited node, so hits times depth per selected counter definition, resident until the tail's verification compares them against the written `:cnt` — and the walk's depth-proportional state that the bounded-memory case already documents; which figures are only proxies (the plan's entry count as the upper bound for mirror residency, the reported free space against the work-directory estimate, which is the per-definition maximum including the reduction pass's transient rather than the selection's total) and how exhaustion leaves a safe prefix (a spill that fails on `ENOSPC` returns a typed error before the first index record is appended, leaving the store unchanged and the run subdirectory removed); and the old index records, which stay live through every retained checkpoint (each lane's checkpoint references them by construction, since a checkpoint's `root` is the content root's record) and are reclaimed only by a `froe compact` run after those checkpoints are released.
7. **Guards, fault tests, interoperability, verification report, known gaps, review:** section stubs — the guards table with the exact header the guide prescribes, a fault table (cutpoint, fault model, named test, asserted prefix), the rest in the prose form the landed cases use — to be filled by tasks 0708, 0709 and 0714.

- **Done when:** the section exists with every subsection `docs/high-risk-changes.md` names, the mutation table has a row per boundary in the architecture under the guide's headings, and each row names the regression test the later task will add, `git diff --check` is clean, and the commit body records the omitted gates.
