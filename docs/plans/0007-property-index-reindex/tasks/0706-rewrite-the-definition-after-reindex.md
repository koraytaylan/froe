# Rewrite The Definition Node As A Reindex Does

Two pieces of policy sit here, both taken from the reindex protocol `docs/analysis/index-definitions.md` records. `definition_update.rs` rewrites a selected definition node with identity preservation: `reindex` set to `false` (a `BOOLEAN`), `reindexCount` incremented from its current value (read converting to `LONG`, as Oak's own increment reads it; a multi-valued value is a typed refusal, since Oak's own commit fails on it) or created at 1, rewritten as a `LONG`, `corrupt` removed, the hidden `:disableIndexesOnNextCycle` set to a `BOOLEAN` `true` (Oak reads that flag strictly as a `BOOLEAN` and sees no other stored type) under the disabler's predicate, which selection evaluates against the store's head and passes in as a verdict, the rewrite itself never seeing a root (`supersedes` read converting to `STRINGS`: an entry names an index that exists and whose `type` does not read strictly as the `STRING` `disabled`, or a `/path/@type` whose `declaringNodeTypes` — read converting to `NAMES` from the head's raw properties, not the model's `NAMES`-only field — still declares it) — froe never disables the superseded indexes itself, Oak's next cycle does, exactly as after an Oak reindex — every hidden child replaced or removed except those whose node carries a `BOOLEAN` `retainNodeInReindex = true` (read strictly as a `BOOLEAN` again, so a `STRING` `"true"` does not retain, while a `STRING` `reindex = "true"` does flag, because that one is read converting), and every other property and every visible child not named in the edits preserved by record identity (the retention rule covers hidden children; `visible_children` exists for plan 0010's `facets` subtree, its first user). `selection.rs` decides what to rebuild and from which state: definitions named by `--index` — an explicitly named definition of an unsupported type is a typed refusal — or, absent that, every definition flagged `reindex=true`, where a type no froe version rebuilds is skipped with a plan warning naming the reason (a `lucene` definition lacking its binary-text policy refuses instead, plan 0010), as Oak's own cycle skips what it cannot index (a definition also carrying a `BOOLEAN` `reindex-async = true`, which Oak's synchronous cycle only moves to `async = async-reindex` — a lane that runs solely when an operator triggers it through Oak's own management interface, and whose completion removes `async` again — is rebuilt here synchronously; a definition already parked at `async = async-reindex` is treated as synchronous before lane resolution — state root the head, the absent `/:async/async-reindex` expected rather than dangling — and its `async` property removed, the state the lane's own switch-back produces on completion; a lane mid-run, with a `/:async/async-reindex` checkpoint present, is out of scope and refused; all recorded at the site with named tests); supported types only (`property`, `reference`, `counter`); a synchronous definition from the head, an asynchronous one from its lane's checkpoint root; typed refusals for `lucene` (until plan 0010), `elasticsearch`, `disabled`, `ordered`, a `valuePattern` regular expression, a mount-fragment storage name, a definition whose `PathFilter` Oak cannot construct (Oak's own cycle skips such a definition when the filter throws on construction, so Oak would leave its `reindex` flag set), a definition whose parent is not `/oak:index` (Oak scopes a nested definition to the node holding its `oak:index`, running a child cycle whose editor root is that node, so its paths are relative to it — refused, never approximated), a dangling lane checkpoint without `--from-head`, a lane absent from `/:async` altogether, which Oak's first cycle treats like a lost checkpoint by diffing from the missing state, with its own typed variant, and a definition that is not `oak:QueryIndexDefinition`. `--from-head` is consulted only for a definition whose lane checkpoint is dangling or absent and ignored for an intact lane: a mirror or unique index is rebuilt from the head, because re-inserting an existing entry leaves `match` and `entry` unchanged and only the randomized `:count_*` estimates drift, while a counter takes the *reset* action — its hidden children removed exactly as a reindex removes them (retained ones kept), every visible property untouched, `ReindexCount::Keep`, nothing built; a definition with no removable hidden child (a hit-less counter, a never-indexed definition, or a rerun of the reset) is `NothingToDo` (rendered `nothing to do`): the plan says so, `apply` neither opens the store nor moves the head, and the outcome reports it — because Oak's replay after a lost checkpoint doubles every counter and Lucene definition on that lane whether or not froe ran, while a definition it finds absent from the missing state with no hidden child it rebuilds from scratch; the plan output and the summary name the reset.

**Steps:**

1. `crates/froe/src/writer/commit.rs`: the existing `rewrite_node_with_child_edits` preserves every property slot and edits children only, and the helper it is built on, `read_node_parts`, is private; add a `pub(crate)` property-editing sibling, `rewrite_node_with_edits(provider, writer, base, edits: &NodeEdits)`, where `NodeEdits` groups the property replacements, the property removals and the child edits beside the existing `ChildEdits`, sharing `read_node_parts` and the same slot-preserving write, so the definition rewrite reuses the commit path's identity discipline instead of imitating it; the public commit API and its feature-map row are unchanged (`commit.rs` is 795 lines; the sibling's tests stay in-module only while the file remains under the thousand-line gate).
2. `definition_update.rs`: `rewrite_definition(provider, writer, definition_record, edits: &DefinitionEdits) -> RecordIdentifier` over that rewrite, where `DefinitionEdits { reindex_count: ReindexCount::{Increment, Set(u64), Keep}, disabler_verdict: DisablerVerdict::{Flag, Leave}, property_replacements, property_removals, visible_children: ChildEdits, hidden_children }` lets plan 0008's importer (`reindexCount` set to the file's value plus one, `:version`, `indexImportState` removed) and the `seed` creation of task 0705's counter and of plan 0010's Lucene reindex compose their bookkeeping into the same single rewrite, with the `retainNodeInReindex` rule, the disabler's flag and an empty `hidden_children` accepted (a counter with no hits, a reference index with no entries).
3. `selection.rs`: `select(provider: &dyn SegmentProvider, head_root, inventory, options) -> Vec<SelectedIndex>` — the provider and head root because three of its outputs are reads, not projections of the inventory: a lane checkpoint's `/checkpoints/<name>/root` record, the disabler predicate over the head's raw `declaringNodeTypes`, and the definition record itself, none of which the inventory carries — carrying the definition, the state root record and the `IndexingState::{Head, LaneCheckpoint { lane, checkpoint }, ResetForReplay { lane }}` (the last for a counter under `--from-head` on a dangling or absent lane); every refusal is a distinct error variant carrying the definition path.
4. Tests: bookkeeping over a definition with `reindexCount` absent, present, with a retained hidden child, with a `STRING`-typed `retainNodeInReindex` (not retained) and a `STRING`-typed `reindex` (flagged), and with a `supersedes` naming an active index (the flag is written) versus a disabled one (it is not); selection over the inventory fixture from plan 0006 for every refusal, both state roots, a `reindex-async` definition, one parked at `async = async-reindex`, a counter on a dangling or absent lane under `--from-head` (`ResetForReplay`), and a multi-valued `reindexCount` refused. Subtrees are compared through the lines of `tooling::digest::digest_repository_excluding` under each path after prefix normalization.

- **Done when:** the rewritten definition differs from the original only in the properties and hidden children the specification names (asserted by comparing the lines of `tooling::digest::digest_repository_excluding` under the two subtrees after prefix normalization), every refusal variant is reachable by a named test, a synchronous definition selects the head root while an asynchronous one selects the record at its lane's checkpoint, asserted by record identity, and the stable host gate passes.
