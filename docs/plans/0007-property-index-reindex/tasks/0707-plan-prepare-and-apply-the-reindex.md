# Plan, Prepare And Apply The Reindex In One Head Move

Assemble the operation under the discipline `froe compact` established. `ReindexOptions` carries private fields with `ReindexOptions::new` and `with_*` setters, as `CompactionOptions` does — private fields, not `#[non_exhaustive]`, are what block a struct literal there — so `index_reindex_tests.rs` builds it the way a downstream crate must and plan 0010's `with_binary_text_policy` composes on a stated contract. `plan_reindex(directory, options)` is read-only and lockless: it opens the repository read-only, selects, and — because the plan an operator confirms must say what will be written — collects and counts the entries without writing — through task 0704's `EntrySink::Count` and task 0705's `count_hits`, so the plan never spills — reporting per definition the entries, estimated record bytes and the spill bytes the sort will need (distinct keys are counted from the sorted sequence and reported exactly in the outcome, the plan giving the entry count as their upper bound for the residency estimate, since counting them at plan time would hold one key per node for a unique index). `PreparedReindex::prepare` follows compaction's protocol step for step, canonicalizing the directory once and carrying it in the plan: `validate_repository_shape` and the two pre-lock apply-identity gates (`validate_apply_environment`, which proves the directory can be fsynced, and `validate_apply_identity`, which proves `journal.log` belongs to the service user) before and again after the lock, then `RepositoryLock::acquire` with `validate_path_identity` as `maintenance/prepared.rs` does, a replan from disk, the directory fingerprint from the maintenance planner's `directory_fingerprint`, the certified archive number from `store_writer::next_cleanup_archive_number`, and the third gate: `validate_metadata_source_apply_identity(directory)`, the plan-independent function task 0715 factored in `apply_identity.rs` from `planned_metadata_sources` and `metadata_source_apply_identity_issue` (compaction's `validate_plan_apply_identity` takes a `CompactionPlan`), which refuses a store whose newest active archive could not be re-owned under `open_prepared`'s `preserve_file_metadata` before anything is written; it holds the lock through confirmation. Every function that protocol is made of is exposed by task 0715, the `refactor:` task this one depends on, so this task edits nothing under `writer/maintenance/` — the free-space read behind the work-directory warning comes from the same place, task 0715 having widened `available_filesystem_bytes` for it; its wiring assertion — an in-crate `#[cfg(test)]` unit test in `writer/index/prepared.rs` reading 0715's observation seam, which records each gate call with the directory it received — is the test tasks 0709 and 0806 cite. `apply` rechecks the fingerprint, then `validate_path_identity` immediately before the destructive step (the fingerprint skips `repo.lock` by design, so only the identity check catches a replaced lock file), opens the store through `WritableRepository::open_prepared` with the shared lock and the certified number (the side-effect-free open `froe compact` uses, which rechecks the number and rewrites no manifest and normalizes no archive before the first index record), and runs the ordered sequence: create the run's subdirectory under the work directory (`ReindexOptions` carries `WorkDirectory::{OperatorNamed(path), Default}`; the plan refuses a froe-named subdirectory left by an earlier run in an operator-named directory and warns about one under the default (one whose lock file is held belongs to a live run and is neither), so the operator learns before confirming; a cancelled confirmation creates nothing), then, per `SelectedIndex`, a `rebuild` dispatch by type — collect into runs, build the index into fresh archives at an archive number above every physical name (additive; nothing existing is touched), rewrite the definition with exactly the hidden children the builders produced (none for a hit-less counter or an entry-less reference set), the counter arm passing task 0705's new `seed` into `DefinitionEdits.property_replacements`, and the disabler's flag when selection's verdict says so, returning a `RebuiltDefinition { path, previous_record, rebuilt_record, report }`, with a reset arm for a counter under `--from-head` on a dangling or absent lane (hidden children removed, `ReindexCount::Keep`, no property edits, no index built, the `report` saying so; a definition with no removable hidden child is `nothing to do`: the store is not opened and the head does not move) and the `Lucene` arm a typed refusal until plan 0010 fills it — then one tail over every rebuilt definition: rewrite the spine to a new super-root, verify every new subtree through the open session with `verify_node_tree` and plan 0006's `check_entries` for the mirror, unique and reference types — every entry's path resolves in the state root and carries the key, under an `EntryCheckBudget` of the collected entry count plus one, never `check`'s walk of every covered node — while the counter's arm verifies that every mirror node's path resolves in the state root and every `:cnt` equals the sum of its children's `:cnt` plus the amount task 0705's `BuiltCounter.credited_by_path` records for that node — the number of its own children that hit, times `bit_mask + 1`, already multiplied — since `check_entries` covers no counter — then one `compare_and_set_head` and one `flush` (which under `open_prepared` seals the archive, syncs the directory, validates the finalized session and only then appends the journal line), then a fresh reopen verifying head identity, `verify_node_tree` over each new subtree and the single new journal line (the entry-side pass runs once, before publication), then the typed `ReindexOutcome`. A lane checkpoint's root is read, never modified.

**Steps:**

1. `plan.rs`: `ReindexPlan` with per-definition `ReindexAction` and warnings (a definition skipped with its reason, a work directory estimate above the reported free space — the estimate being the per-definition maximum of total entry bytes plus the fan-in times the sort budget, since a reduction pass holds that much more until it unlinks its merged inputs, and runs are unlinked per definition, residue under the default work directory), and the residue refusal for an operator-named directory (a duplicate unique key is not a plan warning — the plan holds no keys — but an apply-time refusal that fires when the merge reaches the duplicate, before publication — records already appended for lower keys or for definitions rebuilt earlier stay unreferenced at the head's generation, the before-head-publish prefix); `ReindexAction` and the per-definition `ReindexOutcome` carry a reset variant and a `NothingToDo { reason: NoRemovableHiddenChild }` variant beside the rebuild — `ReindexPlan::is_empty()` (every action a no-op) deciding the path that neither opens the store nor moves the head, a mixed selection rewriting only the definitions with work while the head moves once — and are `#[non_exhaustive]`, as the compaction plan's types are, so plan 0010's Lucene variant never breaks the command's rendering.
2. `prepared.rs` and `apply.rs`: the sequence above with progress steps named per `cli-output.md` — `collecting index entries` and `sorting index entries` opened by the collector itself (task 0704: the walk, then its call to `into_sorted()`, which runs the reduction passes), `writing index records` (counting `WorkUnit::Nodes`, the index nodes written) and `verifying the rebuilt indexes` (`Nodes`) opened here, since a function that reports owns its step — the shape check and the three gates in `prepare`, the fingerprint and path-identity rechecks before `open_prepared`, the run subdirectory — named from a stable hash of the canonical store directory, so residue is per store, and holding a lock file for the run's duration, so a concurrent run on another store is neither refused nor warned about — created before the first spill and removed on return, and the per-type `rebuild` dispatch with its `Lucene` refusal arm.
3. Re-export the public surface (`plan_reindex`, `ReindexOptions`, `PreparedReindex`, `reindex`, the observed twins, mirroring `compact`) through `writer/index/mod.rs`, `writer/mod.rs` and `lib.rs` — the module root carries the `pub use` lines as `maintenance/mod.rs` does — and land the feature map's library row for the property reindex in the same task, in a new numbered library section appended after §6 (`## 7. Indexing`, `| Feature | Java | froe | Status |`, which tasks 0805, 0910 and 1007 extend, so every existing `§N` reference stays valid), marked **Implemented** (beta until plan 0007's review freezes); task 0710 lands the command's row in 0611's §3 block and in the command-surface Maintenance table.
4. A `#[cfg(test)]` perturbation seam in `apply.rs` that alters one written subtree after the builders return and before the tail runs — dropping one `match` property, altering one `:cnt`, or splicing in one or more forged key nodes carrying `match` so the entry pass over-counts — the count matters, since the budget is the collected count plus one and accepts at its limit, so only two spliced nodes exceed it — and the three regressions that use it, as in-crate `#[cfg(test)]` tests in `apply.rs`: both arms of the pre-publication verification and the `EntryCheckBudget` the tail constructs, each reaching `PreparedReindex::apply` rather than the checker in isolation. Because `apply.rs` will also carry task 0708's cutpoints and plan 0010's dispatch arm, keep the three regressions' shared fixture in one helper and split the tests into `crates/froe/src/writer/index/apply/tests.rs`, declared `#[cfg(test)] mod tests;` at the old position, if the file approaches the thousand-line gate `scripts/oversized-files.sh` enforces — the shape and the declaration task 0617 used for the command line. They live in-crate because a `#[cfg(test)]` item is absent from the library an integration test links against — the reason `writer/fault_injection` is `#[cfg(test)]` and every probe test sits beside it, and the reason task 0704 places its merge regression in `property_collector.rs` — so task 0709 cites these three by name the way it cites those.
5. Tests in `crates/froe/tests/index_reindex_tests.rs`: a full run over a synthetic store with every supported type and an empty-value node whose key is `:` (the content tree proven untouched through `tooling::check_consistency` and `tooling::digest::digest_repository_excluding`); the rebuilt subtrees render identically to the independent helper's; the definition bookkeeping, with an `includedPaths` and a `declaringNodeTypes` asserted to survive the apply path unchanged, which is the identity-preservation guard's wiring proof; a run with nothing selected mutates nothing and takes no lock on the dry-run path; a counter reset under `--from-head` on a dangling lane (hidden children gone, visible properties untouched, nothing built, the head moved once) and its rerun yielding the `NothingToDo` variant (rendered `nothing to do`) with the store not opened (file snapshot) and the head unchanged, and a mixed selection of one rebuild and one no-op reset moving the head once; the residue refusal and warning; the run subdirectory removed after a successful run; a file snapshot proving the store is byte-identical until the first index record is appended (no manifest rewrite, no archive rename); the head moves exactly once and `journal.log` gains exactly one line; a rerun over the result rebuilds identical subtrees (determinism); the lock refuses a concurrent holder; the observed and unobserved plans are equal (`an_observed_reindex_plan_equals_an_unobserved_one`); the observed and unobserved applies returning identical outcomes over two copies of one store (`an_observed_reindex_equals_an_unobserved_one`, the apply half the guide's row pins for compaction); the reopened store's rebuilt property-family indexes pass `check(provider, root, definition, budget)` of task 0606 and the rebuilt counter passes its own `:cnt` sum check; an `ObservationLog` run (the recording observer task 0715 moved into `tests/support/observation_log.rs`, reached as `support::observation_log::ObservationLog` because this binary already declares `mod support;` for the layout helper) asserts the number of content walks per confirmed run — the counting walk `prepare` performs, the collecting walk of `apply` and the tail's single verification pass, no more — rather than the step count, since `collecting index entries` opens once per walk and `sorting index entries`, `writing index records` and `verifying the rebuilt indexes` open beside them; and the in-crate wiring unit test asserts through 0715's seam that `prepare` called the shape check and the three gates with the canonical directory.

- **Done when:** every test passes, the three in-crate seam regressions hold — both arms of the pre-publication verification refuse a subtree the seam altered, the entry budget refuses a subtree it spliced two forged key nodes into, and no refusal moves the head — `tooling::check_consistency` and `tooling::digest::digest_repository_excluding` (the library entries behind `froe check` and `froe digest --exclude-subtree /oak:index`) prove the content tree untouched after a run, the reopened store's rebuilt indexes pass plan 0006's consistency check, and the stable host gate passes.
