# Specify The Lucene 4.7 Codec And Record The Feasibility Verdict

Write `docs/analysis/lucene-4-7-codec.md`: the byte-exact write-side specification of every file a fresh single-segment index carries under `oakCodec`, extracted from the Lucene sources oak-lucene vendors at the pinned commit (`oak-lucene/src/main/java/org/apache/lucene/**`, `4.7.2-oak2`), in the style of `docs/analysis/write-*.md` — every field, its encoding, its citation, the reader-side validation that will reject a mistake, and the quirks that look wrong and are not. The read side of the table of contents is already specified in `index-lucene-storage.md` (plan 0008, task 0802) and is cited, not restated. Close with the feasibility verdict the plan's gate needs.

**Steps:**

1. Primitives: the output encodings — variable-length integers and longs, strings, string-to-string maps, string sets; the codec header a file opens with (magic, codec name, version range) and the check a reader applies to it; packed integers in the `PACKED` format (bits per value, block layout, and the header-less writer the enclosing formats embed); the block-packed and monotonic block-packed writers, where a monotonic block is a vlong minimum, then the block's average as the four bytes of a float whose rounding the reader replays by multiplying that float by the index and truncating to a long, then a vint bit width and zigzag-encoded deltas — nothing at all when the width is 0, the common case for a linear address stream — with an average of `0f` for a single value; the small-float quantization a norm byte passes through; and the norm the default similarity computes, which is that quantization applied to the boost multiplied by the reciprocal square root of the term count, where the reciprocal square root is computed in double and narrowed to float once, then multiplied by the float boost — not float arithmetic throughout.
2. Segment descriptors: the `.si` write order — version string, document count, compound flag, diagnostics, file set — where the file set is the one creating the compound file has already replaced with the `.cfs` and `.cfe` names before the `.si` is written, and to which the writer adds its own `.si` name; the commit file's order — header, `version` (a change counter, 0 on a fresh commit, which a directory reader compares to decide whether an open reader is still current, so also consumer-read rather than unread), `counter` (read by no reader but consumed when the index writer derives its next segment name, so the quirks register classifies it the same way, never as unread), then per segment the name, codec name, deletion generation, deletion count, field-infos generation and update files, then user data and the checksum, the whole file written under a pending name and published by rename; the `segments.gen` format and the generation naming (`_0`, `segments_1`, and the rule that gives the next commit file its name); and the codec-selection rule — an explicit `codec` first, else `oakCodec` for a fulltext-enabled definition, else `Lucene46`.
3. Field infos: the `.fnm` per-field bits (`IS_INDEXED`, `STORE_TERMVECTOR`, `STORE_PAYLOADS`, `OMIT_NORMS`, `OMIT_TERM_FREQ_AND_POSITIONS`, `OMIT_POSITIONS`, `STORE_OFFSETS_IN_POSTINGS`), one packed byte carrying the norms type in the high nibble and the doc-values type in the low nibble, `dvGen`, attributes, and the composition rule across documents — index options downgrade to the lesser, `omitNorms` sticky once true, a doc-values type change refused — plus the over-long-term rule: a term above the maximum term length is skipped and its document kept.
4. Stored fields: the `Lucene40StoredFieldsIndex` and `Lucene40StoredFieldsData` codec headers at version 0, the `.fdx` 8-byte offsets, the `.fdt` per-document field count, field number, type bits and values — `FIELD_IS_BINARY = 1 << 1` and the numeric code in three bits at shift 3 (int 1, long 2, float 3, double 4), a binary's length as a vint and its numerics fixed-width big-endian, four bytes for an int, eight for a long and the raw bits of the floating types in four and eight — and the size invariant the writer asserts when it finishes: the `.fdx` length is its header length plus eight bytes per document.
5. Postings: the block size of 128, the per-bit-width format table written into `.doc` right after its codec header (a vint packed-integer version, then 32 vints, one per bits-per-value 1..32, each the packed format identifier shifted left five bits with the bit width less one beneath it; the encoded byte sizes are derived by the reader, never stored), doc-delta and frequency blocks, the `vint` tail, positions with payload and offset deltas, the multi-level skip-list framing (levels highest first, each above level 0 prefixed by its buffer length as a vlong and written only when non-empty, level 0 last and unprefixed, a vlong child pointer after each skip entry at every level above 0 and never at level 0, holding the offset of that entry within the next lower level's buffer, which the reader rebases onto that level's region start) around the field-conditional skip payload, its levels and the multiplier between them, the per-term start and finish, the term metadata layout: the `longs` (`docStartFP`, `posStartFP`, `payStartFP` as deltas from the previous term, reset to absolute values at each block start) and the byte stream in source order (`singletonDocID` as a vint when not -1, then `lastPosBlockOffset` as a vlong for positions fields when not -1, then `skipOffset` as a vlong when not -1) — pulsed for every term with a document frequency of 1 whatever the index options, the frequency being implied by `totalTermFreq`.
6. Terms: the rule that partitions a group exceeding the maximum into floor blocks — entries grouped by the byte following the shared prefix, a new floor block begun once the accumulated count reaches the minimum, and that byte recorded as the block's lead byte — which is not a free choice, because the `.tip` floor payload keys each following block by its lead byte, so a partition splitting one lead byte across two floor blocks yields an index Lucene reads wrongly; then the `.tim` header followed by the postings writer's own embedded header (`Lucene41PostingsWriterTerms` plus the block size 128 as a vint), then the single field directory the file closes with — `NumFields` as a vint, then per field `FieldNumber`, `numTerms`, `rootCode` (length and bytes), `sumTotalTermFreq` (omitted for `DOCS_ONLY`), `sumDocFreq`, `docCount`, `longsSize` — and an 8-byte `DirOffset` to that directory as the file's last bytes; the block encoding, whose two bits are `isLastInFloor` in the header vint (`(entryCount << 1) | isLastInFloor`, always set for a non-floor block) and `isLeafBlock` in the suffix-section length vint (`(suffixBytes << 1) | isLeafBlock`), followed by the stats and metadata sections, at the default block bounds of 25 and 48 entries; the `.tip` header, the per-field transducers whose outputs are a vlong `(fp << 2) | hasTerms | isFloor` — the two flags live here, not in the block — with a floor block followed by a vint count of following blocks and, per block, a lead byte and `((subFp - fp) << 1) | subHasTerms` as a vlong, then the `IndexStartFP` vlongs, one per field, and its own 8-byte `DirOffset`; the reader finds both directories by seeking to length minus eight; and the serialized transducer itself: the format version, the packed flag — Lucene's own terms writer builds unpacked, so unpacked is Lucene's own choice — the empty output, the input type, the start node, the counts, the reversed byte store, the arc flags `BIT_FINAL_ARC`… and the byte-string outputs.
7. Doc values: the `Lucene45` doc-values format (`.dvm` field entries with number, type, the numeric formats `DELTA_COMPRESSED`, `GCD_COMPRESSED` and `TABLE_COMPRESSED` at a block size of 16,384, the binary formats `BINARY_FIXED_UNCOMPRESSED` and `BINARY_PREFIX_COMPRESSED` with interval 16, and the `-1` vint end-of-fields marker both `.dvm` and `.nvm` close with, which the producers read as the loop terminator — a terms dictionary takes the fixed form when every value has one length and the prefix-compressed form otherwise, for `SORTED` and sorted-set dictionaries too; the `missingOffset` written after the format — the `.dvd` position of a one-bit-per-document missing bitset when any document lacks the field, `-1` otherwise, for numeric and binary fields; the sorted-set format vint, `SORTED_SET_SINGLE_VALUED_SORTED` (1) encoding as `SORTED` with `MISSING_ORD = -1` when no document carries more than one ordinal and `SORTED_SET_WITH_ADDRESSES` (0) otherwise, which writes three further entries — the dictionary as a terms dictionary, the flat `ords` stream through the numeric path with storage optimization off, and a doc-to-ordinal index whose metadata is the hard-coded `NUMERIC`, `DELTA_COMPRESSED`, `-1`, the packed-integer version, the data pointer, `maxDoc` and the block size, while its payload is a *monotonic* block-packed cumulative sum of the per-document ordinal counts, so the declared format is inert for that entry — under `.dvm` version `VERSION_SORTED_SET_SINGLE_VALUE_OPTIMIZED = 1`; `.dvd` payloads) and the `Lucene42` norms format (`.nvm`/`.nvd` at norms version 1, its own four numeric formats — of which a norms field always takes `UNCOMPRESSED`, since the norms format asks packed integers for the fastest decode and a norm byte needs all eight bits — `DELTA_COMPRESSED = 0`, `TABLE_COMPRESSED = 1`, `UNCOMPRESSED = 2`, `GCD_COMPRESSED = 3` at a block size of 4,096, not `Lucene45`'s constants).
8. Compound files: the `.cfs` header and concatenated entries, the `.cfe` header, the entry count, then per entry the segment-stripped name — `.fdt`, never `_0.fdt`, the namespace task 0802 reads back — an 8-byte offset and an 8-byte length, and which files stay outside the compound file (`.si`, `segments_N`).
9. Quirks register: the raw-bits rule for a stored float and a stored double, which no other section of this document and no other task pins on its own; every constant copied unchanged across versions, every field written but unread, every place where a valid alternative encoding exists and which one froe chooses — among them the transducer arc form (Lucene's own terms writer allows array arcs, so Lucene emits the fixed-array form — an `ARCS_AS_FIXED_ARRAY` flags byte, a vint arc count and a vint bytes-per-arc — for a node with at least five arcs at depth three or less or ten deeper, while froe emits linear arcs only, which the reader dispatches on per node), the block coder's per-bits-per-value format choice (Lucene's own fastest-format rule yields `PACKED_SINGLE_BLOCK` for 1, 2 and 4 bits; the reader honours the header, so a `PACKED`-only writer is valid) and its `ALL_VALUES_EQUAL` escape (bits-per-value 0 followed by one vint), which Lucene's own writer emits for an all-equal block and froe emits likewise; the `Lucene41NormsData` and `Lucene41NormsMetadata` header names the `Lucene42` norms format still writes.
10. Feasibility verdict, as the document's closing section: for each module in the architecture, the source files read, the estimated line count against the thousand-line limit, and any format feature the consumer needs that the plan cannot write; a go or a no-go with reasons.
11. Add the document's row to the tables in `docs/analysis/README.md`, in the form the plan-0006 rows take (task 0601 step 8).
