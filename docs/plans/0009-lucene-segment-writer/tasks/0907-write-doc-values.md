# Write Lucene45 Doc Values

Implement the `Lucene45` doc-values writer for the three types Oak's document maker uses: `NUMERIC` (the `:dv<name>` ordered longs, dates and doubles Oak writes as numeric doc values — a double doc value is the raw bits of the double, *not* the sortable-long encoding of the indexed double term, and the two differ for every negative double, `-0.0` and `NaN`; `:depth` is an indexed integer term, not a doc value) choosing between `DELTA_COMPRESSED`, `GCD_COMPRESSED` and `TABLE_COMPRESSED` exactly as the numeric branch does; `SORTED` (ordered strings and booleans) with the terms dictionary that branch writes — fixed-length `BINARY_FIXED_UNCOMPRESSED` when every value has one length (a boolean field whose documents all carry `true`), prefix-compressed at interval 16 otherwise — and the ordinal stream; `SORTED_SET` (facets): the single-valued optimization when no document carries more than one ordinal, and otherwise the addresses form — the dictionary, the flat `ords` stream, and a doc-to-ordinal index written with a *monotonic* block-packed cumulative sum of the per-document counts even though its metadata declares `DELTA_COMPRESSED` (the reader decodes it monotonically and ignores the declaration). Documents that lack a numeric or binary field get the missing bitset, while a `SORTED` field's ordinal stream carries `-1` ordinals, no bitset, and is always `DELTA_COMPRESSED`, because that stream goes through the numeric path with storage optimization off: the numeric path writes `missingOffset` pointing at a one-bit-per-document bitset in `.dvd` whenever any document lacks the field (`-1` otherwise), and Oak's `:dv<name>` fields are sparse, so a writer that always wrote `-1` would pass Lucene's own index checker and still misreport which documents have the field; a sorted set is written in the single-valued optimized form (`SORTED_SET_SINGLE_VALUED_SORTED`) when no document carries more than one ordinal, with addresses otherwise, as the sorted-set branch decides.

**Steps:**

1. `doc_values.rs`: `DocValuesConsumer::new(directory_sink, document_count)` — the document count the format takes from the segment info, which the sorted-set addresses entry writes as its leading `maxDoc` before one monotonic address per document. A `NUMERIC` field's own `count` and its missing bitset instead follow their input's length, which must equal that document count because the reader addresses both per document. So the dense streams are the numeric values, the missing bitset and a `SORTED` or single-valued `SORTED_SET` ordinal stream, `-1` for a document without the field; the addresses form's flat `ords` stream — written through the same numeric path, so its `count` is a per-value count — and the terms dictionary, whose count is per term, must never be padded, since each document's slice is the cumulative sum of the per-document counts; then `add_numeric(field, values)`, `add_sorted(field, values, ordinals)`, `add_sorted_set(field, values, document_ordinals)` — every source a `SortedPasses` from task 0702's `into_sorted_passes()` (or, in the vector tests, its `from_sorted_records`), walked through its `pass()` method because the consumer makes a statistics pass, a missing-bitset pass and a write pass over the same input, and `add_sorted`/`add_sorted_set` take the dictionary in value order beside the per-document ordinals in document order — `finish()` writing `.dvd` and `.dvm`, closing `.dvm` with the `-1` vint end-of-fields marker.
2. Unit tests from hand-computed bytes for each format branch and for the `-1` end-of-fields marker, including the table branch (its real condition: at most 256 distinct values, kept, and either an overflowing delta — `max - min` negative, which the raw bits of one negative and one positive double produce — or an ordinal narrower than the delta, with the count within 32-bit signed range; ten values 0..9 would land in `DELTA_COMPRESSED` instead), the gcd branch's bail-out (any value outside ±`i64::MAX / 2` sets the divisor to 1, so `GCD_COMPRESSED` is unreachable for a double `:dv` field of magnitude two or more), the gcd branch, a numeric field some documents lack (the missing bitset), a negative double doc value, a sorted field whose values share one length (the fixed-length dictionary), a sorted set with empty documents, a sorted set that is single-valued throughout (the optimized form), and a sorted set where at least one document carries two or more ordinals mixed with an empty document (the addresses form, asserting the format vint `0`, the `ords` entry and the monotonic doc-to-ordinal index).

- **Done when:** the vectors match and the stable host gate passes.
