# Write The BlockTree Terms Dictionary

Implement the block-tree terms dictionary for the unpacked single-segment case: terms of one field arrive in unsigned byte order with their postings metadata and statistics; the writer groups them into blocks of 25 to 48 entries by shared prefix as the detection rule `docs/analysis/lucene-4-7-codec.md` records, including its floor partition — writing a block at a prefix once its terms and already-written sub-blocks reach the minimum, carrying straggler counts upward and forcing a block at the root — while the block-writing stage only chooses floor or non-floor for a group the detection has already decided on (it emits floor blocks only when a prefix is non-empty *and* its entries exceed the maximum, short-circuiting on an empty prefix, so the root block — reached when finishing the field freezes the frontier down to the empty prefix, where the detection forces a block — is a single block however many entries it holds), writes suffix bytes, statistics and metadata into `.tim`, and builds the field's `.tip` transducer from block prefixes to file pointers plus floor data. A field whose term count is zero contributes no directory entry and is not counted in the field count, since a field's metadata is added only under a positive term count and such a field has no root code — so `finish_field` is a no-op for it. That case is reachable whenever every analyzed value of a field yields no token, which this task's tests and task 0911's corpus both carry. There are no per-field trailers: closing the writer appends one field directory to `.tim` — a vint field count, then per field the field number, `numTerms`, `rootCode` (length and bytes), `sumTotalTermFreq` (omitted for `DOCS_ONLY`, which every untokenized string field is), `sumDocFreq`, `docCount` and `longsSize` — writes each field's `indexStartFP` as a vlong into `.tip`, and closes each file with an 8-byte absolute offset to its own directory, which is the only way a reader locates them (it seeks to length minus eight).

**Steps:**

1. `terms.rs`: `TermsWriter::start_field(field_info)` — which calls task 0904's `PostingsWriter::set_field` and keeps the long count it returns for the directory — `add_term(bytes, term_statistics: TermStatistics { document_frequency, total_term_frequency }, metadata)`, `finish_field(statistics: FieldStatistics { sum_total_term_frequency, sum_document_frequency, document_count })`, `finish()`. The record's three members are exactly the three statistics a field hands over when it finishes: `sumTotalTermFreq`, `sumDocFreq` and `docCount`. `sum_document_frequency` and, for a field with frequencies, `sum_total_term_frequency` are the running sums Lucene's own inversion keeps over the field's terms, the latter `-1` for a `DOCS_ONLY` field and then omitted from the directory. The document count is the one value no accumulation over terms can produce: it is the cardinality of a per-field visited-document set, which task 0910's inversion keeps as a per-field counter the way Lucene's own inversion does — summing the per-term document frequencies would overcount every document holding several terms of one field, which Oak produces for every multi-valued property, and Lucene's own index checker refuses with `docCount for field … != recomputed docCount`.
2. Unit tests over hand-computed layouts, the `.tip` bytes compared with what the `FstBuilder` of task 0903 produces, and the last eight bytes of each file asserted to point at that file's directory: fewer than 25 terms (one root block), a prefix with exactly 48 and 49 terms whose terms are spread so no deeper prefix absorbs 25 of them into a sub-block (the floor split; the block detection counts terms *and* sub-blocks), a field whose root block holds more than 48 entries (still one block, never floored), deeply nested prefixes, a field with one term, a field with no term at all (no directory entry and the field count unchanged), and a `DOCS_ONLY` field beside one with positions and offsets (`longsSize` 1 against 3, and `sumTotalTermFreq` omitted for the first).

- **Done when:** the hand-computed layouts match, a field with no term leaves both the directory and the field count untouched while a `DOCS_ONLY` field writes `longsSize` 1 with no `sumTotalTermFreq` against 3 for a positions-and-offsets field, the `.tip` bytes of each test corpus equal what the `FstBuilder` of task 0903 produces from the expected block prefixes and pointers (the judge's enumeration of those FSTs is the acceptance task 0911 runs), and the stable host gate passes.
