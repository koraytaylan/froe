# Scope — Plan 0010

> Rebuild Lucene indexes natively: reproduce Oak's document model, analyzer chain and numeric encodings so exactly that a real Oak serves the same query results from a froe-built index as from its own, and install the result with the transport and bookkeeping the earlier plans proved.

## Why this plan

Plan 0009 can write any Lucene index; this plan writes the *right* one. What Oak puts in a document is decided by the definition — its indexing rules, their property definitions and their aggregate rules — and by the document maker that walks a node against them, which fixes every field's name, kind, options, norms and doc-value type; how a string becomes terms is decided by Oak's analyzer (the standard tokenizer, the lower-case filter, the word delimiter filter), by the shingle wrapper for spellcheck fields, and by Lucene's numeric term encoding for typed values; when a node is a document at all is decided by Oak's fulltext editor and the definition's path filter. Every one of those is deterministic over the content and readable at the pinned commit, so the same standard applies as everywhere else in froe: exact reproduction, specified in `docs/analysis/lucene-oak-documents.md` and `docs/analysis/lucene-oak-analysis.md` where the Java stays checkable, and proved against the real thing.

The default Sling index the fixture carries is the classic "everything fulltext" shape — `indexRules/nt:base` with `includePropertyTypes = [String, Binary]`, a regular-expression property definition `^[^\/]*$` that is `nodeScopeIndex`, `analyzed` and `useInExcerpt`, and a few excluded names — which is also the skeleton of AEM's `cqPageLucene`, `damAssetLucene` and `lucene` definitions. That shape, with `evaluatePathRestrictions`, ordered properties, null checks (under a rule whose node type is not `nt:base`, since Oak refuses that combination itself), aggregates and facets, is the target.

## In scope

- **Specifications**: Oak's document model (`docs/analysis/lucene-oak-documents.md`, with `lucene-facet` 4.7.2 pinned by artifact and checksum for the facet field and the facet configuration, which Oak does not vendor) and the analyzer chain (`docs/analysis/lucene-oak-analysis.md`), the latter from `lucene-analyzers-common` 4.7.2 sources, pinned by artifact and checksum because the analyzers are not vendored by Oak.
- **Analysis**: the standard tokenizer with its Unicode word-break grammar, the lower-case filter with the consumer JVM's own case mapping, the word delimiter filter with Oak's flag set (word parts and number parts generated, English possessives stripped, no case-change and no letter–digit split, the undelimited original term preserved as well when `indexOriginalTerm` is set), the shingle filter for `:spellcheck`, the path-hierarchy tokenizer for `:ancestors` under `evaluatePathRestrictions`, for `:suggest` the newline-splitting tokenizer Oak's suggest helper supplies when `suggestAnalyzed` is false and the capped definition analyzer when it is true, and the token-count cap at `maxFieldLength` the definition's analyzer is wrapped in, which the writer configuration Oak builds keeps as its default while routing `:spellcheck` and `:suggest` past it; every token with position increment and offsets; conformance proved token by token against the image's classes.
- **Numeric encodings**: Lucene's prefix-coded numeric terms for long, integer and double fields at their precision steps, and the epoch-millisecond long Oak indexes a DATE value as.
- **Documents**: indexing rules and inheritance, property definitions by name and by regular expression (a bounded subset, refused beyond it), typed fields, analyzed fields (`full:` prefix at version 2), `:fulltext`, `:path`, `:ancestors`, `:depth`, `:nodeName`, `:nullProps`, `:notNullProps`, ordered doc values (`:dv`), facets (sorted-set facet fields through the facet configuration's build semantics), spellcheck and suggest fields, aggregates with relative nodes and the reaggregation limit, `useInExcerpt` stored fields, boosts, `maxFieldLength`.
- **Binaries**: only for a binary whose holding node carries `jcr:mimeType`, which Oak's own binary-text extraction requires before it attempts anything (a binary without one produces nothing, whatever the policy): pre-extracted text from a `--pre-extracted-text-directory` in the layout Oak's pre-extracted text store writes when the blob has an external identity; otherwise the operator's explicit choice between the `TextExtractionError` marker Oak writes when extraction fails and nothing. froe cannot evaluate Tika's supported-type set, so `skip` reproduces Oak for unsupported types exactly and differs only where Oak extracts text, while `marker` differs on unsupported types too; the plan output states which policy is in force and how many binaries it touched, and a definition with a `tika` configuration child is accepted — nothing is read from it, since froe extracts no text and the declared binary difference already covers what the configuration narrows — with the plan output stating that a custom Tika configuration is in force (AEM's `damAssetLucene` ships one).
- **The operation**: `froe index reindex` for asynchronous Lucene definitions with the state rule, the `:data` writer, the status and stored-definition bookkeeping, the lane rule (with `--from-head` resetting a definition whose lane checkpoint is dangling or absent, as plan 0007 resets the counter: hidden children removed, nothing built, so Oak rebuilds from scratch — because after a lost checkpoint Oak's fulltext editor re-enters reindex mode on a missing before state at the root and Oak's index writer appends every document again to a retained `:data`, doubling it whether or not froe rebuilt it), one head move, verification; `:suggest-data` left for Oak to regenerate.
- **Evidence**: the `lucene_reindex` interop phase with Oak's own reindex as the oracle through the judge's enumeration, Oak booting and answering the same fulltext, property, ordered and facet queries with the same plans, no reindex logged; safety case and frozen review.

## Out of scope

- Similarity and dynamic-boost fields (`useInSimilarity`, `similarityTags`, `dynamicBoost`), custom analyzers (any child of `analyzers`; only its `indexOriginalTerm` property is read), function-based properties (`function`), `compatVersion 1` definitions, `maxFieldLength = 0` and an `nt:base`-based rule carrying a `nullCheckEnabled` property definition (the combination Oak's own rule validation throws on, so Oak cannot load such a definition at all) — each refused with a typed error that names the feature, never approximated. One refusal is raised at document time rather than at definition load: a DATE property value that does not parse, which Oak's own path also fails the commit on, refused with the path, the property and the value named.
- Text extraction itself (Tika) and the suggester index Oak builds into `:suggest-data` — not refusals but recorded departures: a definition carrying either is processed, the binary-text policy supplies a marker or pre-extracted text in place of extraction, and `:suggest-data` is left for Oak's next cycle to regenerate, which it does whenever the suggestions' `lastUpdated` is missing.
- A hybrid definition — a property definition with `sync` or `unique`, or a `nodeTypeIndex` rule with `sync`, the test `docs/analysis/index-definitions.md` records: Oak's editor also maintains a synchronous property index under the hidden `:property-index`, which this plan does not build; refused by name at definition load.
- A Lucene definition without an `async` property: Oak documents `async` as required and plan 0008 refuses it for the same reason; the reindex refuses it by name.
- Definitions whose codec verdict is not `oakCodec`: Oak's codec selection resolves an explicit `codec` property first, by registered name, and only when it is absent chooses `oakCodec` for a fulltext-enabled definition and Lucene's default `Lucene46` (compressed stored fields, per-field formats) otherwise; plan 0009 writes only `oakCodec`, so any other verdict is refused by name with the codec stated. The `oak.lucene.compressing-codec` system property that selection consults before everything else is a setting on the consumer's own JVM, which froe cannot observe: a recorded departure rather than a refusal, since no guard could arm it.
- The definition-level `valueRegex`, which filters indexed values and node names and drops path-only documents: refused by name.
- Elasticsearch and composite mounts.
- Bringing an index up to date across commits after the indexed state: the state rule of plan 0008 stands.
