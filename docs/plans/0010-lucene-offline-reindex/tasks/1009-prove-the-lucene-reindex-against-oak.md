# Prove The Lucene Reindex Against Oak's Own Reindex

The `lucene_reindex` phase uses the same design as the property phase, for the same reason (a booted Sling writes content of its own, so both rebuilds must index one store): a booted Sling reindexes `/oak:index/lucene` and the variant below (`reindex=true` posted; the `async` lane rebuilds them; the phase waits, through the Sling GET servlet, for `reindex=false` and an advanced `reindexCount` — the hidden `:status` is invisible to JCR and Sling — and asserts a newer `:status/reindexCompletionTimestamp` on the extracted store with `froe node`), Sling is stopped and the store extracted; the phase then checks the extracted `:data` is canonical (zero deletions in every `segments_N`, read by plan 0008's segment reader — a lane cycle between Oak's rebuild and the stop updates documents through Oak's index writer as a delete and an add, and the judge's `enumerate` reads live documents only, so this check is what makes the comparison exact) and repeats the boot, flag, wait and stop sequence (bounded to three attempts) when it is not; exhausting the attempts fails the phase naming the condition; it then copies the extracted store, resets the definitions' bookkeeping on the copy through `definition_edits::reset_reindex_bookkeeping` (`reindex = true`, `reindexCount` set to the extracted value minus one, so that froe's own single increment lands back on the extracted value, whatever the attempt count), and froe rebuilds them on the copy at the lane checkpoint Oak's last cycle recorded in `/:async` — the state the extracted `:data` reflects. The base fixture is enriched in `populate_content` for this phase with content that exercises the definition's branches and AEM's common shapes: a node with a long, a double, a date and a boolean property; a page-like tree with `jcr:content` children; and a second, fulltext-enabled definition variant (a `nodeScopeIndex` and `analyzed` property, so Oak selects `oakCodec`) posted on the fixture's one lane (`async=async`, so a dump of every Lucene definition stays a single-lane selection) with `includedPaths` and `queryPaths` both `/content/interop/variant`, the subtree its content lives in, so plan 0008's phases keep their plans and results — its import phase selects `/oak:index/lucene` explicitly, its dump phase compares per definition (task 0808), and both query under `/content/interop/pages` — with `evaluatePathRestrictions`, an `ordered = true` property definition under its `indexRules` (the new-format form; the old `orderedProps` list is read only by the old-format rule construction, for definitions without `indexRules`), a `nullCheckEnabled` property under a rule whose node type is not `nt:base` (Oak refuses that combination at definition load), a `facets` property and an `aggregates` rule, which `generate` asserts Oak indexed (in `phase_baseline.rs`, as task 0616's assertions are); the phase reindexes both definitions. The phase's suite wiring lands with it. The phase lives in a new `phase_lucene_reindex.rs`, registered in `main.rs`; one file per plan's phases keeps each under the thousand-line gate.

**Steps:**

1. Fixture additions through Sling; the second Lucene definition variant with the features above; every earlier index phase is rerun against the enriched fixture and still passes (the transport phases select and compare per definition, task 0808).
2. Content oracle: dump the extracted store's and the copy's `:data` with `froe index dump`; the judge's `enumerate` output must be identical for every field, term, posting, position, offset, stored value, doc value and norm; document counts equal; `checkindex` clean on froe's.
3. Live oracle: Sling booted on froe's store; `assert_oak_consumed_store_as_written`; no reindex or index-corruption markers; through the query probe, fulltext `CONTAINS`, a `full:` property query, an ordered query with `ORDER BY`, an `IS NULL` query, a facet query (`REP:FACET`), an `ISDESCENDANTNODE` query that exercises `:ancestors`, and a path-restricted query each return the same rows in the same order as on Oak's store, and their `EXPLAIN` plans name `lucene:` indexes with the same plan text; every query meant for the variant is restricted under `/content/interop/variant`, since Oak's own fulltext query planner offers an index with `queryPaths` only to queries restricted at or below them, and its plan must name `lucene:<variant name>`.
4. The binary policy: the fixture's uploaded binary is indexed under `TextExtractionError` by froe and by its extracted text on Oak's side — the one declared difference — so the enumeration comparison applies a posting-level filter to both enumerations before any statistic is derived — removing, for every document that carries that binary's text (the `jcr:content` node that holds it, whose own document the per-property pass fills, and, when an aggregate includes `jcr:content`, its `nt:file` parent), the postings, the stored value and the norm of the field Oak added that text to, dropping terms left with no postings and recomputing document and total frequencies from what remains — `:fulltext` for the node and a non-relative include, `fullnode:<include path>` for a `relativeNode` include; the phase computes the affected document set and field names from the definition's aggregates and asserts the exclusion covers exactly that set; the fixture's binary carries words that occur nowhere else in the content, so the exclusion set is minimal and the coverage assertion checkable.
5. Whole-store delta: the copy's digest before and after froe's run differs only under the rebuilt definitions (`ExpectedDigestDelta::Subtrees`), and `froe check` passes at the new head. The definition node itself is compared as 0712 step 3 compares the property family's: the digest of `/oak:index/<name>` on the extracted store versus froe's copy, excluding `:data`, the `:status` timestamps and `uid`, and the `:index-definition` clone's `reindexCount`, naming the first differing line — the oracle for `facets`, `seed`, `refresh` and the rest of the visible bookkeeping.
6. Wiring: `interop_full` calls the phase after `lucene_writer_conformance`; the run record gains lines stating what it proved, the froe-side edits made to the copy before the rebuild under test (the bookkeeping reset), and the canonical-index check with the attempt on which it passed, read from the `canonical-index-lucene.txt` the phase writes in the work root (its own name, beside the `canonical-index-property.txt` task 0712's phase writes, since one `write_run_record` follows both); `scripts/interop-fixture.sh` accepts the phase name in all three of its lists — the accept pattern, the error text and the header's `(phases: …)` usage block; `docs/interop.md` gains the phase section and its `generate` section is updated for the variant definition and content, `main.rs`'s numbered module-doc chain gains the phase in order, the judge's `Analyze`, `NumericVectors` and `RegularExpressionVectors` classes tasks 1003 to 1005 added, and the updated chain diagram.
7. The reset: on a further copy of the extracted store, remove the lane's checkpoint with `froe checkpoint remove --yes <name>`, run `froe index reindex --yes --from-head --index /oak:index/<variant name>` with the binary policy, assert no hidden child remains and every visible property is unchanged, boot Sling, wait for the lane's cycle, assert Oak logged `Failed to retrieve previously indexed checkpoint`, advanced `reindexCount` by exactly one and rebuilt the definition from scratch (`:data` present); then stop Sling, extract that store and compare Oak's from-scratch `:data` against a froe rebuild on a copy from the lane checkpoint that cycle recorded (the oracle shape of step 2, outside the declared binary difference, bookkeeping reset through `definition_edits.rs`), since the second boot's instance-keyed content makes a comparison against the first oracle non-deterministic; record the scenario in the run record.

- **Done when:** the phase passes against the pinned image with the enumerations identical outside the declared binary difference, every query pair equal, the reset scenario ending in Oak's own from-scratch rebuild, the whole-store delta confined to the definitions, the script, the chain diagram and `main.rs`'s module doc name the phase, and a deliberately wrong position increment in the word delimiter makes the enumeration comparison fail on `:fulltext`, and the stable host gate passes (`--all-features`, so the interop suite is compiled and linted), and every earlier index phase passes against the enriched fixture.
