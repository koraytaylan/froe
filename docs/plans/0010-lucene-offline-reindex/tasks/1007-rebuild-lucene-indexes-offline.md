# Rebuild Lucene Indexes Offline

Add the Lucene branch to the reindex library on the skeleton plans 0007 and 0008 built: selection accepts a `lucene` definition (under `/oak:index` itself: task 0706's nested-definition refusal applies to every type) only when `ReindexOptions` carries task 1006's `BinaryTextPolicy` (set through a public builder method, `with_binary_text_policy`, since `ReindexOptions` is task 0707's type and the command's `index_reindex.rs` is task 0710's file; a pre-extracted directory composing with the fallback for blobs that have no external identity or are missing from it), and the gate is unconditional and refuses rather than skips: a Lucene definition in the selection, named or automatically selected, without a policy refuses the plan naming `--binary-text` (task 0706's skip-with-warning applies only to types no froe version rebuilds), and the command passes no policy until task 1008 adds the flags. The builder is public, so the library capability is reachable from this task on, and its feature-map row (the Lucene reindex as a library capability in the `## 7. Indexing` section, **Implemented**, beta until plan 0010's review freezes) lands here; task 1008 lands the command's row. The features the scope lists as refusals, the definition-level `valueRegex`, any definition whose codec verdict is not `oakCodec` (task 1005), and a definition without an `async` property (refused for the reason plan 0008 gives: Oak documents `async` as required and no Oak oracle exists for the synchronous case) are refused by name; a definition matching no node produces the zero-segment commit of task 0909 (what Oak persists for an empty index; the test asserts `:data` holds exactly `segments_1` and `segments.gen`); the rules' node types resolve against the state root's own `/jcr:system/jcr:nodeTypes`, as Oak's own cycle builds it, from the state it indexes and never from the head; the state root follows the lane rule (a Lucene definition is rebuilt from the checkpoint of the lane its `async` property names under plan 0006's lane rule; a dangling or absent lane checkpoint is refused and `--from-head` resets a Lucene definition as it resets the counter — hidden children removed, `ReindexCount::Keep`, nothing built — because after a lost checkpoint Oak's fulltext editor re-enters reindex mode on a missing before state at the root and its index writer's reindex branch appends every document again to the retained `:data`, doubling the index whether or not froe rebuilt it, while a definition with no hidden child Oak rebuilds from scratch — the plan output states the reset and the reason); the walk applies the definition's path-filter verdicts under the visible-editor filter's visibility semantics, makes a document per included node with a rule, counts the nodes it visits (the counter the safety case's cost statement cites), and feeds each document to plan 0009's writer through `add_document` (the writer spills through `SortedRuns` internally); the segment is written into `:data` through plan 0008's `OakDirectoryWriter` (single segment, compound file), copying the file set `LuceneIndexWriter::finish()` returns (`segments_N` and `segments.gen` plus each segment's `.si` file set — what plan 0008's readers compose, plus the generation file no `.si` names): `_0.cfs`, `_0.cfe`, `_0.si`, `segments_1`, `segments.gen` for a single segment, `segments_1` and `segments.gen` alone for the zero-segment commit — never the directory listing, so a spill file an interrupted merge left behind can never reach `:data`; the definition receives the bookkeeping Oak's own cycle and its fulltext editor perform around a reindex — `reindex=false`, `reindexCount` incremented, `corrupt` and `indexImportState` removed (as Oak's own cycle clears the one and its reindex step removes the other), the hidden `:disableIndexesOnNextCycle` set under the disabler's predicate, `refresh` removed when set (as the editor consumes it when it builds the definition), the `facets` subtree Oak's node-state-backed facet configuration persists (the `facets` node created with `jcr:primaryType = nt:unstructured` as soon as one facet property is indexed, whatever its arity; each `facets/<dimension path element>` carrying `jcr:primaryType = nt:unstructured` and `multivalued = true` for every multi-valued `STRINGS` dimension), `:status` with a fresh `uid` (a `STRING` of decimal epoch milliseconds, distinct from the previous value, as Oak's fulltext editor writes it), `lastUpdated` as a `Date` property whose value is the lane checkpoint's `properties/created` string when it parses as ISO-8601 and the run's current time otherwise (the `indexingCheckpointTime` commit attribute when present and the current time otherwise, as plan 0006's specification records), `indexedNodes`, `reindexCompletionTimestamp` (a `Date`), `:version`, `seed` created if absent, composed into task 0706's `DefinitionEdits` (`ReindexCount::Increment`, `seed` among the replacements, the `facets` subtree among the `visible_children`, the hidden children) so the definition is rewritten once; `:index-definition` replaced by the visible clone of the definition's *pre-run* state (Oak's fulltext editor clones the builder's base state when it enters reindex mode for a new-format definition — `reindex=true`, the old `reindexCount`, no `seed` the run created — and carries no `creationTimestamp`; plan 0008's importer clones the updated state instead), `:suggest-data` removed — then the spine rewrite, verification through the open session before anything is published (the segment readers, the file read-back, plan 0006's inventory), one head move and a fresh reopen. The operation runs through task 0707's `PreparedReindex`: `selection.rs` admits the Lucene definitions, `plan.rs` gains their `#[non_exhaustive]` action variant and plan lines (rule count, document count estimate, the policy in force, the lane and its checkpoint, and a work-directory *proxy*, never called an upper bound, reported as the two byte totals the counting walk can produce without analyzing anything — the bytes of values the rules mark stored, and the bytes of values they mark indexed — together with the figure implementation derives from them. That derivation, and the basis for whatever scaling it applies, is implementation's to choose and to record in `docs/index.md`: nothing in this repository measures bytes per token or bytes per posting, both are workload statistics rather than format facts, and a stated figure would be worse than a named proxy. It must account for the spill runs, which coexist with the assembled segment until `finish()` drains them, and for the compound copy. This is the proxy task 1011's resources section names — which task 0707's free-space warning consumes), and `apply.rs`'s per-`SelectedIndex` `rebuild` dispatch gains its `Lucene` arm — `lucene_reindex.rs` does the document making, writing into a segment directory inside the run's subdirectory (with the reindex's sort budget as the writer's budget) and the `:data` copy, and returns the `RebuiltDefinition` the shared tail publishes with every other rebuilt definition in its one head move, so a mixed selection moves the head once; the open protocol (the shape check, the three apply-identity gates, the lock, replan, fingerprint and certified archive number in `prepare`; the fingerprint and path-identity rechecks and `open_prepared` in `apply`) and its guards are the ones 0709 proved, and this task adds an in-crate `#[cfg(test)]` wiring unit test in `apply.rs` that a Lucene selection reaches that wrapper and its `index-reindex.` cutpoints, rather than repeating the protocol's guard rows. This plan's `### Safety case` section, written by task 1011, receives its fault and guards tables here.

**Steps:**

1. `lucene_reindex.rs` (declared `pub mod lucene_reindex;` in `writer/index/mod.rs`) and the selection changes, `prepared.rs`'s replan rechecking the codec verdict and the binary-text policy under the lock (the facts task 1011's authoritative-state section lists), with the arm's own progress steps `making index documents` (counting `WorkUnit::Nodes`, one document per visited node), `writing index segments` (the `WorkUnit::IndexDocuments` variant task 0910 adds), `copying index files` and `reading back index files` (both `WorkUnit::Files`); the shared tail's `verifying the rebuilt indexes` stays task 0707's, since a function that reports owns its step.
2. Cutpoints (each attempt assembles into a fresh segment directory inside the run's subdirectory, so a dead run's complete segment is never mistaken for this attempt's; after every death variant the parent reacquires `repo.lock` and reruns the operation, asserting the residue behaviour of the left-behind run subdirectory and the same published post-state), each armed under the `lucene-reindex.` prefix by its own test in both fault models through the child harness, which gains a Lucene-reindex entry point in `test_support.rs`, at the seams `lucene_reindex.rs` owns (plan 0009's `finish` is one call, so the two work-directory cutpoints sit on either side of it): `lucene-reindex.after-last-document` (after the last `add_document`, before `finish`: spilled runs and partial stored-field files in the run's subdirectory), `lucene-reindex.after-segment-finished` (after `finish` returns, before the first `:data` record: a complete segment in the subdirectory), and `lucene-reindex.mid-file-copy`; the publication and verification boundaries are `apply.rs`'s, armed by task 0708 as `index-reindex.before-head-publish`, `index-reindex.after-head-publish-before-flush` and `index-reindex.before-applied-verification`, and a wiring test proves a Lucene selection reaches them. The process-death tests run through the child harness of `fault_injection::test_support`: `CRASH_EXIT_CODE` at the armed cutpoint, `VERIFIED_EXIT_CODE` after the error child's assertions, and the parent's fresh reopen proving the prefix.
3. Tests over synthetic stores (the content tree proven untouched through `tooling::digest::digest_repository_excluding`): a full rebuild of a definition with every supported feature; a definition whose facet properties are all single-valued getting an empty `facets` node; a stray file planted in the segment directory absent from `:data`; determinism across two runs (byte-identical `:data` apart from `uniqueKey`, timestamps and `uid`, `dirListing` as a set); the lane rule; the `--from-head` reset (hidden children gone, visible properties untouched, nothing built) and its rerun yielding the `NothingToDo` variant (rendered `nothing to do`) with no head move; a `supersedes` naming an active index (the flag is written); the refusal of each unsupported feature, of `valueRegex`, of a non-fulltext definition, of a hybrid definition, of a definition without `async` and of a missing binary policy; the visited-node counter against the oracle walk; the in-crate wiring unit test that the branch runs through `PreparedReindex`; a file snapshot proving the store byte-identical until the first record is appended; the head moves once; and the observed and unobserved plans equal for a Lucene selection, which task 0707's own equality test cannot reach because its store carries no Lucene definition.
4. `crates/froe/tests/lucene_reindex_guard_tests.rs` and the safety case: the fault table naming every cutpoint and its test, and the guards table with neutralization evidence for the new refusals, the lane rule, the empty-plan short circuit (`ReindexPlan::is_empty()`; neutralization: run the tail anyway), the by-name `:data` copy (neutralization: copy the directory listing instead), the `--from-head` reset (neutralization: rebuild from the head; the regression asserts no `:data` child and every visible property unchanged; the Oak-side proof is task 1009's reset scenario), the policy gate, the disabler's flag written only under its predicate, the document-time refusal of an unparseable DATE value (regression: a run over a store whose one node carries an unparseable DATE, reaching `PreparedReindex::apply`, asserting the store unchanged by file snapshot and the run subdirectory removed; neutralization: skip the field instead), the read-back verification before publication (regression: an unreadable `.cfs` planted in the assembled segment directory, the run refused before the head moves; neutralization: publish without reading the segment back) — the guard plan 0008's import states at the same boundary, which 0709's rows predate because plan 0007's Lucene arm was a refusal until this task filled it — and the three writer refusals task 1011's case cites — a boost on an `omit_norms` field, a first token with position increment 0, a doc-values type change — whose named regressions task 0910 landed and whose neutralization runs in that landed writer, recorded the way tasks 0709 and 0806 record theirs, the neutralization experiments performed serially against a separate target directory with labelled logs and the code restored and rerun after each.

- **Done when:** every test passes, the observed and unobserved plans are equal for a Lucene selection, every cutpoint is armed by a named test that fails when it is removed and the process-death tests prove the scenario ran through the harness's scenario-specific exit codes (`CRASH_EXIT_CODE` at the cutpoint, `VERIFIED_EXIT_CODE` after the assertions) and the parent's fresh reopen, every guard row quotes an observed failing result, the rebuilt index parses under plan 0008's readers with the expected document count, `tooling::digest::digest_repository_excluding` (the library entry behind `froe digest --exclude-subtree /oak:index`) proves the content tree untouched, and the stable host gate passes.
