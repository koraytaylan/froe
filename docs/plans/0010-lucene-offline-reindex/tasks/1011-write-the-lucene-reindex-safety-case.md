# Write The Lucene Reindex Safety Case

The native reindex publishes through task 0707's `apply.rs`, so its case cites plan 0007 for the publication boundaries and plan 0008 for the `:data` write and its `OakDirectory` preconditions; what it adds — spill files and a segment assembled outside the store, the file copy into `:data`, the lane rule for Lucene definitions, the codec-verdict and `valueRegex` refusals, the document-time refusal of an unparseable DATE value, the writer's own typed refusals that plan 0009 installs and this plan publishes through (a boost on an `omit_norms` field, a first token with position increment 0, a doc-values type change), the binary-text policy — is decided here, before any of the plan's mutating code lands, as `docs/high-risk-changes.md` asks. Write the `### Safety case` section of this plan's `ARCHITECTURE.md` in the form tasks 0701 and 0801 use, as the living record task 1007 fills and task 1010 freezes. The task is numbered after the review task because it was added later; 1007 depends on it, so the ordering the guide wants holds.

**Steps:**

1. **Scope and retention.** What survives: the content tree, every checkpoint, every definition not selected, every visible property and child of a selected definition other than `reindex`, `reindexCount`, `corrupt`, `indexImportState` (rewritten or cleared as Oak's reindex does), a `seed` the run creates, `refresh` (removed when set, as Oak's cycle consumes it), the `facets` subtree the document maker persists (created on the first facet property; per-element children carrying `jcr:primaryType` and, for `STRINGS` dimensions, `multivalued`), and the hidden `:disableIndexesOnNextCycle`, written under the disabler's predicate, `/:async`; what is replaced: `:data`, `:status`, `:index-definition`, `:suggest-data` removed (and, under a `--from-head` reset, removed without replacement); what is never read or written: any binary's bytes (froe never extracts; the policy supplies text or a marker).
2. **Authoritative state.** The lockless preview; `prepare` running the repository-shape check and the two pre-lock apply-identity gates, taking the lock, repeating both, replanning, fingerprinting, certifying the archive number and running the metadata-source gate as plan 0007 does; `apply` opening through `WritableRepository::open_prepared` after the fingerprint and path-identity rechecks; the facts rechecked: the definition set, each definition's lane and checkpoint, the codec verdict, the binary policy, the head.
3. **Mutation and publication order.** The existing `### Mutation and publication order` section of `ARCHITECTURE.md`, cited by its heading rather than copied; its rows follow the guide's headings, with the shared publication and verification rows cited from plan 0007's table (the Lucene branch publishes through task 0707's `apply.rs`, so the cutpoints are 0708's and the guard rows 0709's) and the `OakDirectory` write mechanism and its read-back precondition cited from plan 0008's, while the two work-directory rows are boundaries the native reindex adds, which the import has none of, and the `:data`-copy and definition-rewrite rows are restated because their edits, cutpoints and preconditions differ from the import's — each row with the named regression it will get.
4. **Interruption prefixes, observed outcomes, resources.** The old-or-new-head rule inherited from plan 0007; the outcome reporting documents made, segment bytes, files copied and the head before and after; the writer's memory budget (plan 0009), its per-field resident state — the visited-document counters and the field-infos table, proportional to the distinct field count, uncharged because the format itself requires them — the document maker's per-node state, the spill directory's worst case (postings, doc values and norms for the whole index), the terms writer's pending blocks (proportional to a field's term count divided by the minimum block size of 25, charged to the writer's budget by task 0910; Lucene carries the same on a merge), the open-file bound (task 0702's fan-in plus one for the spill inputs, because task 0910 runs its merges one at a time, plus the named constant of segment outputs open at once), the asymptotic time cost (two walks of the state per confirmed run as in plan 0007, the inversion's sort and merge passes over the spilled postings, one pass per codec file — pinned by task 0910's merge-pass counter and task 1007's own visited-node counter), and the temporary segment's disk footprint, with the proxies named (task 1007's work-directory proxy against the reported free space, named as a proxy, with the two byte totals it rests on and the basis implementation recorded for the figure it derives from them) and the exhaustion prefix stated (a spill or segment write that fails on `ENOSPC` returns a typed error before the first `:data` record, the store unchanged and the run subdirectory removed); the old `:data` records stay live through every checkpoint that references them (each lane's, by construction) until a compaction after their release.
5. **Guards, fault tests, interoperability, verification report, known gaps, review:** section stubs — the guards table with the exact header the guide prescribes, a fault table (cutpoint, fault model, named test, asserted prefix), the rest in the prose form the landed cases use — to be filled by tasks 1007 and 1010.
