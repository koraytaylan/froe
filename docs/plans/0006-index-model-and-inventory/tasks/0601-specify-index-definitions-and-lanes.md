# Specify Index Definitions, Lanes And The Reindex Protocol

Write `docs/analysis/index-definitions.md`: the byte- and behaviour-exact specification of everything froe must read from `/oak:index` and `/:async`, of the bookkeeping Oak performs around a reindex, and of the JSON form oak-run prints definitions in, so the later mutating plans implement against a specification rather than against a recollection. This is the prime directive applied to indexing: the Java is ground truth, the document is derived, and every statement cites the file and method it was read from at commit `4984c4cf26a7ca58ae9ce12c63190b7f492bda78`, noting any point where `oak-segment-tar` 1.90.0 differs. The task lands after the two storage specifications because it owns the `docs/analysis/README.md` rows for all three documents.

**Steps:**

1. Record definition discovery and identity: a definition is a child of `oak:index` with `jcr:primaryType = oak:QueryIndexDefinition` and a `type`; non-root definitions are enumerated only when `oak:QueryIndexDefinition` is among the node-type index's `declaringNodeTypes`; the `disabled` type and `:originalType`; `supersedes`, `tags`, `selectionPolicy`, `queryPaths`, `useIfExists`, `deprecated`. Record which reads are type-strict and which convert: the indexer reads `type` and `jcr:primaryType` strictly and sees nothing unless the stored types are exactly `STRING` and `NAME`, so a definition whose `type` is a `String[]` is silently skipped by the indexer, whereas the node-type test converts to `STRING` and accepts the same definition; the model follows the indexer and reports an Oak-ignored definition as a warning rather than converting it.
2. Record the `async` property and lane naming: the lane name is the one value that is neither `sync` nor `nrt`, and zero candidates and several candidates are both refusals Oak throws on; which definitions a synchronous cycle selects and which an asynchronous one does; that a definition without an `async` property is synchronous; that a property name is a lane name exactly when it is `async-reindex` or ends in `async`; and the four `/:async` properties per lane — the lease, the last-indexed-to date, the `-temp` list and the checkpoint value. Record what a dangling checkpoint causes: Oak reports that it failed to retrieve the previously indexed checkpoint and re-runs the initial index update, and that re-run is an incremental diff from the missing state over the hidden state still on disk, not a reindex, because the reindex test is false once a hidden child exists. Record the one exception the Lucene plans rest on: the fulltext editor enters reindex mode whenever the before state at the root is missing, so it *appends* every document again to the retained `:data`, doubling the index.
3. Record the reindex protocol Oak's own editors follow, because plans 0007 and 0010 must leave a definition in exactly this state. What makes a cycle reindex a definition: two gates first — a missing or `disabled` `type`, read converting to `STRING`, and an index mode that does not match the cycle, unless the type is `elasticsearch` — and then either a `reindex` value that converts to `true`, unless the run was told to ignore reindex flags through the system property `oak.indexUpdate.ignoreReindexFlags`, false by default, or through the same switch set on the editor provider; or a definition absent from the before state's `oak:index` with no hidden child other than ones flagged `retainNodeInReindex`, which is the path the ignore switch does not suppress. What the reindex then does: increments `reindexCount`, removes every hidden child except those flagged `retainNodeInReindex`, clears the `corrupt` flag, and sets the hidden `:disableIndexesOnNextCycle = true` when the definition's `supersedes` names an index that exists and whose `type` does not read as the `STRING` `disabled` under the strict read — a `NAME`- or array-typed `type` counts as active — or names a `/path/@type` entry still declared by that index; the importer's data step raises the same flag. The next incremental cycle then sets `type = disabled` on a superseded path entry, removes the named type from a `/path/@type` entry's `declaringNodeTypes`, and removes the flag only when at least one entry was acted on. Record the type strictness of the flags: `reindex` is read converting to `BOOLEAN`, so a `STRING` `"true"` flags a definition, while `retainNodeInReindex`, `reindex-async` and `:disableIndexesOnNextCycle` are read strictly and see only a stored `BOOLEAN`, so the flag froe writes must be a `BOOLEAN`. Record the `reindex-async` switch to the `async-reindex` lane, and what Oak's missing-provider strategy does when a definition's `type` has no registered editor provider. Record that every index update Oak drives is wrapped in the visible-editor filter, at all five of its sites: the reindex composite, the synchronous incremental editors, the asynchronous lane, the importer's catch-up diff, and the out-of-band build. Record, finally, that the disabler reads `supersedes` converting to `STRINGS` and the superseded index's `declaringNodeTypes` converting to `NAMES`, its `type` read being the only strict one it performs.
4. Record the status and stored-definition nodes. `:status` carries `uid` — a `STRING` holding time-increasing decimal epoch milliseconds, read back strictly — `lastUpdated`, which is the `indexingCheckpointTime` commit attribute when present and the current time otherwise, `indexedNodes`, a per-cycle counter every new editor context resets rather than a document count, and `reindexCompletionTimestamp`. `:index-definition` holds a visible clone of the definition with no `creationTimestamp`: the builder's *base* state on a reindex, unless the definition was rewritten in the same commit, so the clone carries `reindex = true` and the old `reindexCount`, and the updated state on an import. `creationTimestamp` is written only where the `refresh` flag is consumed, so after a Lucene reindex or import it is absent until a later refresh writes it — which the inventory and the import both expect. `:version` is a hidden property on the definition node itself, written on every Lucene reindex when the editor enters reindex mode; record it beside the rule that determines an index's format version, and the `seed` written for async definitions. Record what makes a Lucene definition hybrid, which plans 0008 and 0010 both refuse by citing this document: a property definition carrying `sync` or `unique`, or a `nodeTypeIndex` rule carrying `sync`. Record that it is Oak's *incremental synchronous* editor, never the reindex, that maintains the synchronous half in the hidden child `:property-index` — the reindex declines that branch outright, returning no editor for it — and that the child is created and flagged `retainNodeInReindex` on first use. That is why the flag exists: the asynchronous reindex which replaces `:data` must leave the synchronous half standing. Record too that this is the only child Oak ever flags, the corollary plan 0008 rests on when it says the retain rule never fires on an import. Record the drift rule whole, since task 0605 builds from this document: the comparison ignores `reindex`, `reindexCount` and every hidden *property* name, over a visible clone of the current definition — hidden properties kept, hidden child nodes dropped — compared with the stored node as it stands, which is itself an Oak-written visible clone, so cloning both sides is equivalent; a visible child added or removed is a difference; a visible child present on both sides is compared by the same filtered rule recursively, so the ignored names apply at every depth, not only on the definition node. That is what froe's `definition_drift` reproduces. State that only the fulltext editor family writes `:status` — on writer close, and on the reindex path, which also removes `reindexCompletionTimestamp`, while the Lucene importer removes the whole node — and that the property, reference and counter editors never do.
5. Record the out-of-band import protocol as the reference for plan 0008: `indexer-info.properties` and its `checkpoint`, read from the root directory the importer is handed, whose direct subdirectories are then scanned for indexes; `index-details.txt` with `metaFormatVersion`, `indexPath`, `creationTime` and one `dir.<filesystem name>=<jcr name>` line per directory; and `index-definitions.json`, which Oak's own definition updater applies. That file is mandatory — the importer's constructor checks that it exists — and applying it replaces the whole definition node with the file's state, adding or preserving a `jcr:uuid` where the target needs one; the oak-run command of the same name is only a wrapper around that updater. Record the lane switch and its properties — `async-previous`, `temp-<lane>`, `none`, and the revert that sets `refresh = true` — the importer's four steps and its `indexImportState` property, the release after the import of the checkpoint `indexer-info.properties` names unless `oak.index.importer.preserveCheckpoint` is set, and the out-of-band reindex lane name `offline-reindex-async`. Record what an oak-run out-of-band build prints into `index-definitions.json`: it dumps the lane-switched *copy* after that copy's reindex and after the lanes are switched back, so the file carries `reindexCount` one above the store's, `refresh = true` from the revert, a `seed` when the run created one, and — because the reindex filter `{"properties":["*","-:childOrder"],"nodes":["*","-:index-definition","-:data","-:suggest-data"]}` excludes only those three children — the copy's `:status`; the importer's data step then applies that state and increments `reindexCount` once more, so an oak-run import ends two above the original store. Record two more facts plan 0008 rests on: the copy's reindex also cleared the visible `corrupt` property and removed `indexImportState`, so the dumped file lacks both whenever the store has them; the file's key set is `--index-paths` when oak-run was given them and the index path service's enumeration otherwise — and since that enumeration refuses outright when `/oak:index/nodetype` is absent or its `type` does not read as the `STRING` `property`, an oak-run dump over a store whose nodetype index is disabled produces no file at all, which is the case plan 0008's import meets rather than a malformed file; and the catch-up step skips the `sync` lane, which Oak's source marks as unimplemented, while the lane revert is reached on the success path only from the asynchronous catch-up — the failure handler reverts every lane — so oak-run's own importer leaves a lane-less definition sitting on `async = temp-sync`. There is no Oak reference behaviour for importing a synchronous Lucene definition, which is why plan 0008 refuses it.
6. Record the definition printer's output, the format `froe index definitions` must reproduce byte for byte. The printer walks the index paths Oak's path service yields, in an order that has two branches and is never a sort: `/oak:index`'s stored child order filtered to children whose `jcr:primaryType` reads strictly as the `NAME` `oak:QueryIndexDefinition`, taken whenever the node-type index does not declare `oak:QueryIndexDefinition` through a strict `NAMES` read — a `STRINGS`-typed declaration takes this branch even though the property-index lookup would select the index converting, and the Sling fixture takes it because Oak's initial content creates that index with `declaringNodeTypes` null; and otherwise the node-type index's own mirror walk over `jcr:primaryType` and then `jcr:mixinTypes`, depth-first and de-duplicated by path, which mirrors a converting read and so can list a definition the first branch omits. Record the two preconditions that throw before either branch is chosen: the lookup must find, for `jcr:primaryType` and for `jcr:mixinTypes` alike, a `property` definition that lists the property and has an `:index` child — the first in `/oak:index` order whose `declaringNodeTypes` names `oak:QueryIndexDefinition` or a supertype, else the first without `declaringNodeTypes`, one naming other types being skipped, and not necessarily `/oak:index/nodetype` — and `/oak:index/nodetype` must itself exist with a `type` that reads strictly as the `STRING` `property`. Record the serialization: the definition node under the filter `{"properties":["*","-:childOrder"],"nodes":["*","-:*"]}` — every property except `:childOrder`, hidden properties such as `:version` and `:originalType` included, in stored order, then the children `:childOrder` names when that property exists and every child in stored order otherwise, with hidden children excluded by the `nodes` filter — each value carrying its type code, and a plain `STRING` escaped with a `str:` prefix whenever the type-code splitter recognizes a prefix in it: one starting with `:blobId:`, or of length four or more with `:` at index 3, whether or not the code is known, so `jcr:title` renders as `str:jcr:title`; `[0]:<Type>` for empty typed arrays of every type except `STRING`, whose empty array renders as `[]`; binaries base64-encoded, with a refusal at or above `oak.serializer.maxBlobSize`, 1 MiB by default. Record the two-phase string escaping: the first phase scans for `"`, `\`, characters below U+0020 and high surrogates — DEL and the C1 range are emitted raw — and appends the string untouched when nothing matches; only then does the escaping phase run, emitting `\"` and `\\` first, then `\b \f \n \r \t`, and lower-case `\uXXXX` for other controls and for either half of an unpaired surrogate, so a lone low surrogate stays raw unless the string also carries a trigger. Record the pretty-printed layout — a two-space indent unit, one member per line, `{}` for an empty object, arrays inline with `", "` separators, a space after every other token — and the filter variant an out-of-band build dumps with, which drops `:index-definition`, `:data` and `:suggest-data` and keeps `:status` and every hidden property.
7. Add an "AEM safety invariants" section in the style of the existing analysis documents: which properties an offline tool may write, which it must never touch (`/:async` lane checkpoints belong to the lane, not to one index), and the observable consequence of each mistake.
8. Add the three index documents — this one, `index-property-storage.md` and `index-lucene-storage.md` — to the tables in `docs/analysis/README.md`, and record there the precedence rule this plan applies: where trunk at the pinned commit and the consumer build differ, the consumer build's behaviour wins and the specification says so.
9. Record the path filter's construction, which no other document covers: the two absolute-path refusals and the unification, in the order Oak applies them — every include and exclude checked for absoluteness first; then an include equal to or under an exclude dropped, an include under another include dropped as redundant, and, the rule an implementer will not guess, every exclude that lies under no include dropped entirely; then the refusal of an include set left empty. Record also that a single `String` value reads as a one-element list, and that an empty include and exclude set together include everything.
