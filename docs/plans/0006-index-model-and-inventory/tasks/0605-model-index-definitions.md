# Model Index Definitions, Lanes, Status And Path Filters

Create the `froe::index` module and its typed model of the three structures the specification names: `IndexDefinition` discovered under `/oak:index` (root level, plus non-root definitions found by walking for `oak:index` children when the node-type index declares `oak:QueryIndexDefinition`), `AsyncLanes` read from `/:async`, the `StatusNode` and `StoredDefinition` beside a definition, the `PathFilter` with its three verdicts, and the prefix form of `ValuePattern`. Every reader in this module and the ones later tasks add takes `&dyn SegmentProvider` plus a root record, as `content::NodeState` does, so the mutating plans can run the same readers over an open write session before publication, not only over a `Repository`. Every field is a typed value, never a string the caller re-parses; every malformed input is a typed error naming the definition path.

**Steps:**

1. Create the `froe::index` module root (`pub mod index;` in `lib.rs`, since the model is consumed by the command crate and by integration tests) together with documented stub modules for every file this plan's later tasks own — `property/mod.rs`, `counter/mod.rs`, `lucene/mod.rs`, `inventory.rs`, `definitions_json.rs` — and for `definitions_json_reader.rs`, which plan 0008's importer fills, each holding only its module comment, so the later tasks fill files that already compile and never contend for `index/mod.rs`.
2. Define `IndexType` (`Property`, `Reference`, `Counter`, `Lucene`, `Elasticsearch`, `Disabled { original }`, `Ordered`, `Unknown(String)`) and `IndexDefinition` with the fields the architecture lists, reading each property with the type strictness the specification records for the Oak reader that consumes it: a `type` that is not a single `STRING`, or a `jcr:primaryType` that is not a single `NAME`, is what Oak's indexer skips, so the model reports the definition as ignored by Oak — an `IndexWarning`, never a conversion; `propertyNames` is read converting, as the editor reads it, with a warning when the stored type is not `NAMES`, because the query planner's strict read would then never select the index, a single-valued `NAME` reading as empty there too, while the node-type index's own lookup converts with a warning and still selects it; `declaringNodeTypes` is read strictly as `NAMES`, anything else yielding a predicate that matches nothing, with the same warning; `unique` is read strictly as a `BOOLEAN` — `true` selects the unique strategy, anything else the mirror strategy, with a warning for a non-`BOOLEAN` value — and every reader and builder selects the strategy through this one field; `includedPaths`, `excludedPaths` and `valuePattern` follow the strict and converting rules the specification states, a `valueIncludedPrefixes` array that is not `STRINGS` draws the same indexed-but-never-selected warning as a non-`NAMES` `propertyNames`, a `valueExcludedPrefixes` array that is not `STRINGS` draws a query-correctness warning because the planner ignores the exclusion and answers from an index lacking those values, and a single non-`STRING` prefix value is refused with a typed error because Oak itself throws on it.
3. Implement lane resolution as the specification records it: a definition without an `async` property is synchronous; with one, `Option<String>` for the lane and a typed error for zero candidate names as well as for several (an `async` property holding only `sync` or `nrt` is one Oak refuses), `IndexingMode` flags for `sync` and `nrt`.
4. Implement `PathFilter::from_definition`, `filter(path)` with `Include`, `Exclude` and `Traverse`, and `include_paths()` returning the unified include set — unified, not raw, since that is the set the filter actually admits and the set task 0611's budget derivation iterates — applying, in order, the absolute-path refusal over both sets, then the unification `docs/analysis/index-definitions.md` records — an include equal to or under an exclude dropped, an include under another include dropped as redundant, and every exclude lying under no include dropped entirely — then the refusal of an include set left empty by it. A `String` value reads as a one-element list, and empty include and exclude sets together include everything. Both refusals are typed errors, as Oak's own filter construction refuses both.
5. Implement `ValuePattern` as one value carrying `included_prefixes`, `excluded_prefixes` and an optional regular-expression text — all three coexist on a definition, which the composed rule requires — whose `matches` answers with the typed `Unsupported` error rather than a guess only when that rule actually reaches the pattern, never merely because one is stored.
6. Implement `AsyncLanes::read(provider: &dyn SegmentProvider, content_root)` returning, per lane, the checkpoint, the pending list, the lease and the last-indexed-to date, plus `dangling_checkpoints(provider: &dyn SegmentProvider, super_root)` resolving against `/checkpoints` every UUID-shaped string value of every non-`-temp` property on `/:async`, whatever the property name — the digest's deliberately conservative rule, kept so that task 0611's delegation narrows nothing — the same resolution `froe digest` performs in its private `dangling_async_checkpoints`, reimplemented here in `lanes.rs` because `tooling/digest.rs` belongs to task 0613's footprint and the two tasks run in parallel — a deliberate, temporary duplication documented in `lanes.rs`, pointing at the digest, as `CONTRIBUTING.md` asks, until task 0611 removes the duplicate; task 0611, which depends on both, makes the digest delegate to `AsyncLanes::dangling_checkpoints`.
7. Implement `StatusNode` and `StoredDefinition`, `definition_drift(definition, stored)` — its diff rendered as froe's own sorted list of changed paths rather than the JSOP text Oak's index printer emits, a departure recorded at the site — with the semantics `docs/analysis/index-definitions.md` records: Oak clones only the current definition, stripping hidden children and keeping hidden properties, and compares it with the stored node as it stands, ignoring `reindex`, `reindexCount` and hidden *property* names and counting a visible child added or removed as a difference and comparing a visible child present on both sides by the same rule, recursively — the ignore set, the base one and the caller's extra one alike, governs property names at every depth, not only on the definition node, so a child differing only in a hidden property such as `:childOrder` is no difference; froe clones both sides, which is equivalent because every Oak-written `:index-definition` is itself a visible clone, and the module comment says so. The comparison takes an extra ignore set the caller may pass, which is how plan 0008 excuses the properties an oak-run build rewrites. `index_paths(root)` yields definition paths in the printer's order, with a typed error raised before either branch is chosen — the printer's own precondition — when `/oak:index/nodetype` is absent or its `type` is not the `STRING` `property`, so a disabled nodetype index refuses whatever it declares. Then the fallback branch, filtered to children whose `jcr:primaryType` is a `NAME` reading `oak:QueryIndexDefinition`; or else the node-type index's mirror walk, when it declares `oak:QueryIndexDefinition` through a strict `NAMES` read — the walk of whichever property index Oak's lookup selects for `jcr:primaryType` and for `jcr:mixinTypes`, chosen among `property` definitions, their `type` read converting and arrays skipped, whose converting `propertyNames` read contains the property and whose `:index` exists: the first whose converting `declaringNodeTypes` names `oak:QueryIndexDefinition` or a supertype wins immediately, one naming other types is never selected, and the first without `declaringNodeTypes` is the fallback, which in the fixture is `/oak:index/nodetype`, whatever precedes it. A second typed error covers the case where no such index has an `:index` child, which is the state Oak itself throws on.
8. Tests: synthetic stores written through the writer holding every definition variant present in the real fixture (a `unique` index, one with `declaringNodeTypes`, the counter with `seed`, the Lucene definition with `:status`, `:index-definition`, `:version` and `:data`), malformed cases (multi-valued `type`, a `NAME`-typed `type`, zero and two lane names, a `STRING` and a single-`NAME` `propertyNames`, a non-`NAMES` `declaringNodeTypes`, a `STRING` `unique` that reads as mirror, a single non-`STRING` prefix that is refused, non-absolute `includedPaths`), both `index_paths` branches and the nodetype-index precondition, and lane parsing over the exact `/:async` property set the fixture has (`async`, `async-temp`, `async-LastIndexedTo`).

- **Done when:** the model round-trips every fixture in `crates/froe/tests/index_definition_tests.rs`, each malformed input yields the named typed error or warning, `froe::index` is documented at module level with the format facts it relies on, and the stable host gate passes.
