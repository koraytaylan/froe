# Build The Oak-Side Judge Inside The Pinned Image

The interop suite proves froe's writes by making a real Oak consume them. For indexes it also needs to *ask* Oak questions — what its printers say about a store, whether Lucene's own index checker accepts a directory, how many documents an index holds, what Oak's own dumper reads out of `:data` — without publishing a second image or adding a dependency. The pinned Sling image ships a full Temurin 21 JDK (`javac`, `jshell`), the Oak 1.90.0 runtime bundles under `/opt/sling/artifacts` (`oak-core`, `oak-store-spi`, `oak-search`, `oak-segment-tar`, and `oak-lucene-1.90.0.jar`, which inlines Lucene 4.7.2 with its own index checker and carries the `META-INF/services` registration of `oakCodec`), but not `oak-run` or `oak-run-commons`. Every class the judge uses therefore comes from a shipped bundle, and where a plan relies on an `oak-run-commons` helper the judge re-implements it from those classes. Add a `judge/` directory of small Java classes — one per subcommand family, so later plans add classes instead of growing one file, each kept under a thousand lines by convention since the Rust gate does not see Java — compiled together in a one-off container from that image and run by class name with `java -cp`, plus the Rust harness that drives them.

**Steps:**

1. `judge/StoreSupport.java`: opens the fixture as a segment node store through Oak's own read-only file-store builder, the way `oak-run-commons` opens one for a fixture, from shipped classes alone, with the store mounted read-only in the container. `judge/IndexJudge.java`: `definitions <store>`, which prints Oak's definition printer in JSON over the index paths Oak's own path service yields, and `info <store>`, which prints Oak's index printer in JSON over an index-information service bound to the Lucene and property-index providers and to the async-lane service. `judge/LuceneJudge.java`: `checkindex <directory>`, Lucene's own index checker, exiting non-zero unless the verdict is clean; `numdocs <directory>`, Oak's own document count over a directory, whose name is Oak's; `dump <store> <indexPath> <outputDirectory>`, Oak's own dumper reading `:data`; and `sample-index <directory>`, a small single-segment index of a handful of documents written with Lucene's own writer under the configuration Oak builds for a definition node carrying `codec = oakCodec`, since Oak selects `oakCodec` only for that property or for a fulltext-enabled rule — one commit into a local filesystem directory, a few kilobytes, so later tasks can commit a real `oakCodec` index without committing the fixture's megabyte-sized compound file. No build tool, no dependencies beyond the image's jars; the class path is every jar under `/opt/sling/artifacts` joined by `find`, and `javac` succeeding is the assertion that every class the judge needs is in the image, the Felix inventory types the index printer implements included.
2. `judge.rs`: `Judge::compile()` runs `javac` over every `.java` under `judge/` once per suite process in a container with the sources bind-mounted, caching the class directory in the work root under a name derived from a hash of the sources *and* the resolved image reference `sling_image()` returns, so neither a changed judge nor a different image (the canary's floating tag included) ever runs against stale classes from an earlier run; `Judge::run(class_name, arguments, mounts)` runs `java -cp <classes>:<jars> <class_name>` with the store mounted read-only and returns standard output, asserting exit status the way `froe()` does, beside `Judge::run_failure(class_name, arguments, mounts)`, which asserts a non-zero exit and returns standard error as `froe_failure` does beside `froe` — the corrupt-directory assertion of this task's phase and every later refusal assertion use it. The output conventions for every subcommand later tasks add, one of four: a class producing a single committed fixture prints it on standard output, which `Judge::run` returns and the fixture's header records the redirection for (`counter-vectors`, `vectors`, `regular-expression-vectors`, `analyze`); a class whose artefact is a file the phase reads back, committed or not, takes an explicit output path (`numeric-vectors <outputFile>`, `enumerate <directory> <outputFile>`); and a class that renders only a verdict commits nothing and writes nothing to standard output, exiting non-zero on the first failure with the offending item named on standard error, which `Judge::run_failure` returns (`fst-check`); and a class whose output the phase parses rather than commits prints it on standard output, with the phase stating what it reads from it (`consistency`); failures print the JVM's own diagnostics.
3. `podman.rs`: a `run_one_off(container: &OneOffContainer { image, mounts, entrypoint }, arguments)` helper reused by both, with the same timeout discipline the rest of the suite has.
4. A `judge_smoke` phase that compiles the judge, runs `dump` on the fixture's `lucene` index and `checkindex` against that dump (a directory froe has *not* produced), proving the class path resolves `oakCodec` and that a clean verdict is reachable, and runs `sample-index` followed by `checkindex` and `numdocs` on its output, asserting its `segments_1` names `oakCodec` and its file set is `_0.cfs`, `_0.cfe`, `_0.si`, `segments_1`, `segments.gen`; and `checkindex` on a copy of the dump with one byte of `segments_1` overwritten, asserting a non-zero status.

- **Done when:** `judge_smoke` passes against the pinned image, the judge refuses an obviously corrupt directory with a non-zero status, and the stable host gate passes (`--all-features`, so the interop suite is compiled and linted).
