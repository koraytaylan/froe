# Add The Read-Only Index Commands

Add the `froe index` command group with its three read-only subcommands, each opening the store exactly as `froe summary` does — no lock, no manifest write, no file created — and each rendering through a new `index_display.rs` under the output contract of `docs/cli-output.md`: data on standard output, progress and warnings on standard error, counts with thousands separators, byte sizes in binary units. User-facing documentation moves with the code, so this task also writes `docs/index.md` and updates the three inventories that would otherwise misstate what froe can do.

- `froe index list REPOSITORY` prints the inventory as a table plus warnings; `--index PATH` (repeatable) narrows it, and a path that names no definition in the store is a typed refusal naming the path, for all three subcommands — a nested definition is not that case, since the inventory carries it, so it is listed and rendered here and refused only by the reindex.
- `froe index definitions REPOSITORY [--output FILE] [--index PATH]…` prints oak-run's JSON; `--output` never overwrites, like `froe export`, and refuses a path inside the store directory through `froe_export::output_file::create_export_output`, the existing file-case helper (the dump's directory case applies the same rule through the shared helper `tooling::output_directory::refuse_output_inside_repository`, which carries the directory-case traversal and message; the dump adds its own emptiness check in `refuse_existing_dump_output`, task 0803) — deliberately unlike `froe digest --output`, which truncates, because a definitions file is an artifact an operator keeps and re-imports, and the divergence is stated in the guide.
- `froe index check REPOSITORY [--index PATH]…` runs the mirror, unique and reference consistency check of task 0606 (the counter has none; `check` says so per definition) — each definition against the state it indexes, the head for a synchronous one and the lane's checkpoint for an asynchronous one, with a dangling or absent lane checkpoint reported as "cannot be checked" rather than inconsistent — and, independent of `checked_state_root` because it reads the definition subtree at the head and needs no lane state — so a dangling lane never makes a Lucene definition uncheckable — the level-1 Lucene blob check of a new `index/lucene/check.rs` (registered in `index/lucene/mod.rs`, which task 0802 later extends with its structural report so the two halves of the Lucene check sit together), which streams every binary property under the definition subtree as oak-run's level-1 check does (hidden children included, so mount-decorated data children are covered), aggregated into one typed report the display module only renders; prints one verdict line per index, and exits 0 when every checked index is consistent, 3 when any is inconsistent, and 4 when none is inconsistent but some index that has an applicable check could not be run — a dangling or absent lane checkpoint, a budget refusal, or a definition the inventory could not model. A definition whose type has no applicable check, the counter and the disabled, Elasticsearch and unknown types among them, is reported per definition and does not reach exit 4, or no unnarrowed run could ever exit 0, every store carrying a counter, so a runbook that gates on the command never passes over an index nobody checked — 3 and 4 rather than 1 or 2, since the binary already returns 1 for a runtime failure and leaves 2 to the argument parser, and an inconsistent index must not look like a store that would not open — the exit code contract oak-run's `--index-consistency-check` never had and an operator's runbook needs.

**Steps:**

1. Extend `Command` in `command_line.rs` with `Index { action: IndexAction }` and put `IndexAction` with the three read-only variants in the new `command_line/index.rs` (declared `pub(crate) mod index;` there — the room task 0617's split made, and the file the later plans' `Reindex`, `Dump` and `Import` variants extend, so `command_line.rs` itself gains one variant and nothing more); doc comments double as `--help` and state the read-only guarantee in the same words the other read-only commands use.
2. `checked_state_root(provider, super_root, definition) -> CheckState::{Head, LaneCheckpoint { lane, checkpoint }, Uncheckable { reason }}` beside `AsyncLanes` in `index/lanes.rs`, since the property family's verdict rests on it and its placement is not Lucene's to own: the head for a synchronous definition, the lane's checkpoint for an asynchronous one, and `Uncheckable` when that checkpoint is dangling or absent. Then `index/lucene/check.rs`, registered in `index/lucene/mod.rs`: the level-1 blob pass streaming every binary property under the definition subtree, hidden children included, exactly as oak-run does, returning one typed report the display module renders.
3. Dispatch in `main.rs` beside the inspection commands; `tooling/digest.rs`'s private `dangling_async_checkpoints` delegates to `AsyncLanes::dangling_checkpoints`, removing the duplication task 0605 recorded and replacing `lanes.rs`'s duplication note with a doc comment naming the digest as its caller and the conservative rule it keeps — landed as this task's first, separate `refactor:` commit with no behaviour change (`digest_tests.rs`'s `a_checkpoint_that_async_still_references_but_no_longer_exists_is_reported` passes unmodified; the shape-rule unit test `a_checkpoint_reference_is_recognized_only_in_oaks_shape` moves from `digest.rs`'s test module to `lanes.rs`'s with the function it exercises; `commit.rs`'s conservative twin in `remove_unreferenced_checkpoints` is left as it is) before the commit that adds `Index`; implement rendering in `index_display.rs` with the sanitizing helpers every other display module uses for repository-controlled text; the progress steps are `inventorying indexes`, opened by `IndexInventory::collect` itself (task 0609), for `list` and `definitions`, and `checking indexes`, opened here, for `check` — a function that reports owns its step, so the command never wraps a step around a call that opens one.
4. Register `index.rs` (the read-only commands' tests; the mutating commands' tests live in per-plan files, `index_reindex.rs` and `index_transport.rs`, registered by the tasks that create them) in `crates/froe-cli/tests/command_line_tests/main.rs` and write the command-line tests (an asynchronous property definition checked against its lane, a dangling lane reported as uncheckable, a store whose counter estimate is unavailable checked unbudgeted, an `--index` path naming no definition refused by name, a definition whose derived budget the walk exceeds reported by name with exit code 4, and the three exit codes 0, 3 and 4 asserted exactly, including exit 0 over a store carrying a counter definition, whose type has no applicable check — the budget's own limit and limit-plus-one boundary is task 0606's, at the library entry where a test can set it, an `--output` path inside the store refused): each subcommand over a synthetic store, `--output` refusing to overwrite, the check's exit code on a forged `match`, the reporting-stream invariants (`--silent`, `--progress always`, byte-identical standard output), and the read-only invariant in the form `diagnostic_command_tests.rs` already uses — a directory snapshot byte-identical after each subcommand and no `repo.lock` created or touched; the `command_line_tests` binary cannot reach `directory_snapshot` today (its `mod support;` resolves to `command_line_tests/support.rs`), so `crates/froe-cli/tests/command_line_tests/main.rs` gains `#[path = "../../../froe/tests/support/filesystem_snapshot.rs"] mod filesystem_snapshot;` — the same relative path `crates/froe-cli/tests/support/mod.rs` already uses, three levels up from `command_line_tests/` to `crates/` — which the later index command tests share.
5. `docs/index.md`: what an Oak index is in froe's terms (definition, lane, storage), the three read-only subcommands with examples, what `check` proves and does not prove (level 1 for Lucene; the structural check for the property family; no query-time semantics), the check's three exit statuses and what each means for a runbook — why a narrowed `--index` run of `definitions` succeeds on a store whose nodetype index is disabled while an unnarrowed one refuses, and why `list` runs on such a store either way, reporting a warning that the non-root definitions could not be enumerated; the `NodeCheckBudget` refusal task 0606 defines, whose limit `froe index check` derives rather than taking from a flag, one budget per definition as `check` itself takes one per call, from task 0607's `estimated_node_count(p, CountBound::Maximum)` summed over that definition's unified include set — `/` when that set is empty, and always `/` for a `reference` definition, whose editor Oak builds with no path filter, so its `includedPaths` bound a budget while the walk covers the store.
